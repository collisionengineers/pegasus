# Fixture strategy

## Safety boundary

`sample-doc-files/` is not a test corpus. It contains a copied home-profile shape and potentially private material. Test tools must never recurse through it, hash it wholesale, upload it or use it for discovery. It remains ignored and untouched for its owner to assess separately.

Only files named in a reviewed manifest may enter a test run. Corpus loaders reject paths that escape their fixture root, reparse points, caches, profile directories and entries without provenance and licensing fields.

## Fixture roots

```text
tests/fixtures/
  synthetic/       # small generated byte/structure cases owned here
  specifications/  # redistributable examples from exact cited specifications
  upstream/        # minimal licence-reviewed reference-regression inputs
  private.local/   # optional local-only manifested fixtures; ignored and never published
  manifests/       # reviewed JSON manifests selecting each lane's inputs
```

Organise owned cases by `pdf/`, `doc/`, `docx/`, `msg/`, `eml/` or a named shared capability. Do not copy any upstream corpus blindly. Any selected external fixture must be relevant to a documented behaviour, retain its source path and revision, and pass fixture-level licence review.

## Manifest contract

Each entry records:

- stable fixture ID and SHA-256;
- relative path, byte length and detected/expected format;
- provenance URL/path, source revision and licence decision;
- PII classification and publication permission;
- represented feature tags and owning `EXT-*` units;
- expected extraction outcome;
- enabled test lanes and any platform restriction.

Synthetic fixtures should be generated in test code when a small byte sequence clearly expresses the case. Binary fixtures are reserved for behaviour that cannot be represented clearly and reliably in code.

## Corpus gates

1. Resolve and verify path containment; refuse reparse points.
2. Verify every declared byte length and hash before parsing.
3. Run with input, decoded-output, object-count, nesting, allocation and time limits.
4. Disable execution and retrieval of scripts, actions, templates, images, hyperlinks and other external references; record passive evidence only.
5. Write results under `TestResults/` or ignored `artifacts/` without copying input content, sensitive filenames or extracted text into logs.
6. For genuine-data runs, record the snapshot manifest hash before and after evaluation and qualify any drift.
