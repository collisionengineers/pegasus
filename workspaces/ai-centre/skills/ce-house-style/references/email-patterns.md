# Email & Correspondence Patterns

> **Source-workspace boundary:** This file is package-local evidence or an experiment only; it is not a Pegasus caller, policy, current instruction, or acceptance authority. `Pegasus.Core`, current operator authority, and an authorised human own every accepted fact, cost, category, outcome, legal position, send, report issue, and approval.


## Greetings

- Informal / ongoing: *"Good morning,"* · *"Good afternoon,"* · *"Hi [Name],"*
- Formal documents: *"Dear Sirs"* · *"FAO: The Court"* · *"FAO: The Instructing Solicitor"*

## Three standard message shapes

### 1. Report / document delivery — most common, very short

> Good [morning/afternoon],
>
> Please see attached [report / estimate / valuation / audit / rebuttal].
>
> Any issues let us know.
>
> Kind regards,
> [Name]

Notes: one sentence per element. No summary of what the document contains. No sign-off flourish.

### 2. Technical clarification / defence — short to medium

Structure: **clear opening statement → what was done → why it was done → why it is reasonable / justified → calm closing reassurance.**

> We have reviewed [the matter / your query of DD/MM/YYYY].
>
> [What was done, in plain terms.]
>
> [Why it was done — cite the standard, rate, guideline, or evidence.]
>
> We consider this reasonable because [brief justification].
>
> [Optional: independence line if dispute context.]
>
> Any further queries, please let us know.

Use this same structure for insurer, TPI, solicitor, repair-cost, salvage, valuation, diminution, and
methodology challenges after the relevant specialist skill has set the technical position.

### 2a. Holding response - evidence missing

Use when a query has been supplied without the underlying CE report, estimate, valuation, photos,
previous correspondence, or other evidence needed for a substantive position.

> We can respond, but the underlying CE report and supporting evidence should be reviewed before a
> substantive position is issued. Please provide the report, estimate or valuation, photographs, and
> any previous correspondence. If a holding response is required now, we can acknowledge the query and
> confirm that the engineering position will follow once the evidence has been reviewed.

### 3. Chasing / status update — short

> Good [morning/afternoon],
>
> We are writing to chase [matter / reference / outstanding instruction].
>
> [Specific request for action, one sentence.]
>
> Kind regards,
> [Name]

No apology unless responsibility is genuinely owned. No emotional language. Direct request.

## Preferred stock phrases

| Context | Phrase |
|---|---|
| Sending a document | *"Please see attached…"* |
| Closing an email | *"Any issues let us know."* |
| Opening a defence | *"We have reviewed…"* |
| Justifying a figure | *"We consider this reasonable because…"* |
| Citing a standard | *"We have followed [ABP rates / Glass's Guide / Thatcham / CPR guidance]…"* |
| Qualifying a judgement | *"We consider"* · *"the evidence indicates"* · *"on the information provided"* |
| Closing a dispute | *"We see no reason to deviate…"* |

---

## Conciseness spectrum

| Situation | Default length |
|---|---|
| Report delivery | Very short (3–4 lines) |
| Clarification | Short–medium |
| Dispute / defence | Medium–long |
| Internal coordination | Short |

Default to brevity. Expand only where justification is required. Never summarise a document's contents in the covering email — the document speaks for itself.

---

## Response strength for challenges

Use the lowest response strength that protects CE's position:

| Strength | Use when | Pattern |
|---|---|---|
| Initial explanation | The query is reasonable, the issue may be misunderstanding, or evidence is incomplete. | Acknowledge the query, state what was reviewed, explain the CE position with one or two concrete reasons, and invite specific contrary evidence. |
| Firm follow-up | CE has already explained the position or the challenge repeats an unsupported point. | Confirm the point has been reviewed, state the supported conclusion, identify why the opposing position is not accepted, and ask for specific evidence. |
| Final position | Evidence is complete enough and the engineer/client wants a final answer. | State CE's final position, summarise the key evidence, and say the position will be reconsidered only if new material evidence is produced. |
| Escalate before drafting | The response would make a legal concession, contradict a CE report, depend on incomplete material evidence, or rely on unverified OEM/FCA/FOS/ABI/vendor material. | Stop and ask for engineer or solicitor review before drafting. |

Tone controls:

- Be direct and factual.
- Do not accuse the opponent of bad faith.
- Do not use exclamation marks or informal emphasis.
- Do not over-explain obvious points; one strong paragraph is usually better than a long defence.

## Report register phrases (formal, from actual CE reports)

- *"In accordance with your instructions received on [date], our findings are as detailed below:"*
- *"We consider that an equitable settlement would be [figure]."*
- *"It is our professional opinion that…"*
- *"We have proceeded on that basis throughout."*
- *"This addendum is to be read alongside our original report and supersedes nothing contained within it."*
