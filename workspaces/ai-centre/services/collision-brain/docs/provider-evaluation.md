# Executive experimental shortlist

1. **Cloudflare Workers AI `@cf/baai/bge-small-en-v1.5` at native 384 dimensions.** This is the lowest-friction hosted dimensional match: Cloudflare documents a 384-dimensional response for this model, and the 2026-07-29 pricing page gives an ongoing **10,000 Neurons/day** allowance plus a list rate of **$0.020 per million input tokens** (1,841 Neurons/M); use beyond the allowance requires Workers Paid ([model](https://developers.cloudflare.com/workers-ai/models/bge-small-en-v1.5/), [pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/)). It still needs a new Collision Brain HTTP adapter, preprocessing parity proof, rate/error tests, and approved external-data terms.
2. **Self-host `BAAI/bge-small-en-v1.5`, then `intfloat/e5-small-v2`, in an isolated CPU inference container.** Both first-party model cards identify MIT-licensed, English, 384-dimensional models with 512-token input handling; BGE and E5 require their documented query/passage preprocessing to be benchmarked exactly ([BGE card](https://huggingface.co/BAAI/bge-small-en-v1.5), [E5 card](https://huggingface.co/intfloat/e5-small-v2)). This route preserves the current vector schema and provides model-family diversity, but adds model serving, image/supply-chain pinning, cold-start, patching, and capacity work. It is an experiment beside the .NET 10 service, not a replacement runtime.
3. **Google `gemini-embedding-2` with `output_dimensionality: 384`, using synthetic/approved text only.** Google marks the model stable, supports dimensions **128–3072**, and recommends 768, 1536, or 3072; therefore 384 is schema-compatible but deliberately below the recommended sizes and must earn its place on retrieval quality ([model specification](https://ai.google.dev/gemini-api/docs/models/gemini-embedding-2)). Google lists text input as free of charge on the Free Tier and **$0.20/M input tokens** on the Paid Tier, but also says Free-Tier content is used to improve products while Paid-Tier content is not ([pricing](https://ai.google.dev/gemini-api/docs/pricing)).
4. **OpenAI `text-embedding-3-small` with `dimensions: 384` as a low-cost paid comparator.** The model defaults to 1,536 dimensions, accepts an API dimensions parameter for shortened vectors, and has an 8,192-token maximum input; the price page lists **$0.02/M input tokens** and does not list an embedding free allowance ([embedding guide](https://developers.openai.com/api/docs/guides/embeddings), [pricing](https://developers.openai.com/api/docs/pricing)). This remains adapter work and a paid experiment even if the absolute token charge is small.

**Decision position:** do not select any route until the same authorised corpus proves retrieval quality, warm/cold latency, ingestion throughput, failure behaviour, measured total cost, and acceptable privacy/residency terms. Public leaderboards and model-card scores are screening evidence, not Collision Brain evidence.

## Dimension decision

- **First gate:** run every shortlisted route at exactly 384 dimensions and keep each model’s vectors in an isolated index/database. Never mix embedding identities or dimensions.
- **Dimension reduction, no migration:** `gemini-embedding-2` explicitly supports 384 within 128–3072, although Google recommends larger sizes; OpenAI exposes a dimensions parameter to shorten its v3 vectors ([Google model specification](https://ai.google.dev/gemini-api/docs/models/gemini-embedding-2), [OpenAI embedding guide](https://developers.openai.com/api/docs/guides/embeddings#reducing-embedding-dimensions)).
- **Native migration-required comparators:** Gemini’s recommended 768/1536/3072 sizes, OpenAI’s default 1,536, BGE base/large, BGE-M3, and other non-384 models require an experimental migration plus full re-index before a fair native-dimension test. Do not truncate a model unless its owner documents that capability.
- **Escalation rule:** consider a cloned 768-or-larger schema experiment only if every credible 384 route misses a pre-registered retrieval-quality threshold. That experiment still proves neither migration approval nor provider selection.

For a bounded experiment, test compute in this order only after local proof: **(1) Azure Container Apps app + finite Job, (2) Cloud Run service + Job, (3) OCI Always Free VM for the self-hosted 384-dimensional CPU route**. # Benchmark and decision gate

## Controlled experiment

1. Obtain explicit approval for a bounded synthetic or separately authorised evaluation corpus and for each external API. Do not use `corpus/` merely because a provider has a free tier.
2. Freeze the same source set, chunking, normalisation, retrieval weighting, `k`, filters, and relevance judgements. Pin provider/model/revision, vector dimensions, tokenizer/preprocessing, distance metric, and index parameters.
3. Create isolated 384-dimensional indexes for: current `local-hash` regression baseline; Cloudflare BGE; self-hosted BGE; self-hosted E5; Gemini Embedding 2 at 384; and OpenAI `text-embedding-3-small` at 384. Re-embed both documents and queries for every candidate.
4. For the two BGE routes, compare returned vectors or retrieval rankings on identical inputs. Any difference becomes preprocessing/serving evidence, not an assumed provider equivalence.
5. Measure:
   - retrieval recall@k, MRR/nDCG, and citation usefulness against reviewed judgements;
   - ingestion documents/tokens per second, total re-index duration, and index size;
   - warm and cold lookup p50/p95, worker cold start, timeout/rate-limit/retry behaviour, and recovery after interruption;
   - measured input tokens/characters/requests, compute duration, egress, storage, database, logs, and resulting account quote;
   - data-use, retention, deletion, subprocessor, and regional-processing fit for the exact account and endpoint.
6. Pre-register minimum quality, latency, rebuild/RTO, privacy, reliability, and monthly-cost thresholds before viewing results. A free allowance, low list price, or public benchmark score cannot pass a candidate by itself.

## Pass / stop rules

- **Pass to a deeper experiment only** when the candidate meets every pre-registered gate and its model identity, dimensions, preprocessing, rate limits, price basis, and data terms are reproducible.
- **Stop** a route on unacceptable retrieval/citation failures, unapproved content use or geography, unstable capacity, unbounded retry/cold-start behaviour, inability to rebuild, or a total-cost estimate outside the authorised ceiling.
- If no 384-dimensional route meets quality, request a separate migration experiment for a documented larger native dimension and full re-index. Do not reinterpret that request as migration, spending, deployment, or provider-selection approval.
- Final provider selection remains **not evidenced** until representative quality, latency, cost, privacy/residency, recovery, security, and real-caller acceptance all exist under the project’s authority gates.
