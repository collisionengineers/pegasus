# UX and component guidance

Read this when a task needs more than a small page adjustment.

## Useful lenses

- **Task fit:** Can the user recognize what this screen is for, find the next action, and understand its consequence?
- **Hierarchy:** Do order, grouping, spacing, headings, and emphasis reflect importance rather than decoration?
- **Efficiency:** Is routine work direct without making uncommon or risky actions too easy to trigger accidentally?
- **Feedback:** Does the interface distinguish working, completed, empty, invalid, partial, stale, and failed states honestly?
- **Recovery:** Are errors specific, associated with the affected control or action, and recoverable without losing valid work?
- **Predictability:** Do focus, selection, navigation, and controls behave consistently with the platform and the rest of the product?
- **Accessibility:** Prefer semantic HTML and native controls; ensure meaningful names, relationships, order, keyboard operation, visible focus, adequate contrast, and alternatives to colour or motion.
- **Responsive use:** Preserve meaning and operations at supported widths and zoom. Dense desktop tools may reflow into sections, tabs, or horizontal scrolling where the relationships remain clear.

## Components, patterns, and libraries

A component is a reusable interface part. A pattern explains how parts work together to meet a recurring user need. A design system may combine components, patterns, tokens, content guidance, and implementation assets.

Before choosing or designing a component, identify the user need and context, its content and anatomy, supported states and variants, keyboard/focus/labelling behavior, responsive behavior, and when it should or should not be used.

An existing library component is a starting point, not proof that it fits the workflow or is accessible in context. Avoid selecting a library for appearance alone. Consider consistency, interaction quality, accessibility evidence, customization cost, asset weight, maintenance, licensing, and fit with the project's server-rendered model.
