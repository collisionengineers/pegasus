# Optional brief overlay — UI/UX

Copy this prompt set into the brief when the ticket changes a user interface.

- **States:** specify loading, empty, error, disabled, and success behaviour that the surface can reach.
- **Access:** state keyboard interaction and accessibility requirements, including focus and semantic feedback where relevant.
- **Responsive constraints:** name the sizes, density, or layout limits the implementation must preserve.
- **Visual proof:** define the screenshot or observable interaction that demonstrates the intended result.
- **Scope boundary:** do not bundle an unrelated redesign with the requested UI change.
