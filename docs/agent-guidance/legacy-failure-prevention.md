# Preventing a repeat of the predecessor

The predecessor was examined as failure evidence. It is not a source tree to migrate.

## What failed

- Roughly 1,400 ticket files, 55 check scripts, 58 package scripts, 126 agent files, and very large generated ledgers made repository consistency a product of its own.
- Runtime components could be registered and extensively tested without receiving the real traffic they were meant to handle.
- Intake orchestration accumulated classification, parsing, routing, persistence, and integration responsibilities in one large file.
- The parsing/OCR engine existed in three source locations; changes and fixes could drift.
- Classification evidence precedence was implicit. Sender identity could beat stronger content evidence and route real work incorrectly.
- Idealized sender fixtures passed while real staff-forwarded QDOS mail failed.
- Broad verification proved that repository artifacts agreed with each other, not that the operator workflow worked.

## Pegasus response

| Failure | Required response |
|---|---|
| Governance outgrew product evidence | One AGENTS contract, a few focused skills, one local check, no generated status ledger |
| Registered but uncalled runtime | Name the caller and prove a real input traverses it before calling the capability complete |
| Giant orchestrator | Business decisions in Core; adapters and hosts only translate/orchestrate their own boundary |
| Three engine copies | One implementation; share through project references, never copy source |
| Implicit classification precedence | A documented ordered evidence policy with contradiction tests |
| Synthetic-only fixtures | Genuine corpus sample first, synthetic edges second |
| Author graded own interpretation | Independent reviewer tests literal source rules |
| Dark code retained for future use | Delete or leave unbuilt until a current caller exists |

## Delivery proof for the first vertical slice

The first QDOS slice must take genuine local instruction material through the same entry point the deployed worker will use, create or propose the correct case identity, persist through the actual application boundary, and show the operator-visible result. Unit tests alone are insufficient.
