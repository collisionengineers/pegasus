# Mockup generation prompts

All three used the built-in image generation tool in `ui-mockup` mode. The supplied intake dashboard screenshot was a structural/style reference, not an edit target.

## Concept 1

High-fidelity 16:9 operations cockpit for a small Collision Engineers office: charcoal left navigation, white header, queue cards for Not ready, Review, Held; inbox cards for Receiving work, Queries, Other, Needs sorting; operational lists for Due today and Chasers due (7 days); separate In today case-created activity; paired today/this-week activity cards for Sent to Engineer and Reports sent; Recent activity. Warm off-white, white panels, charcoal, near-black, CE red accents, amber and navy state accents, system sans, 2px corners, border-first, restrained shadows, Lucide-style icons. Keep Triage in separate navigation/workflow, not the inbox categories, and do not conflate In today with Due today. No gradients, glass, decoration, Azure/cloud/AI/developer language, or watermark.

## Concept 2

High-fidelity 16:9 split-pane intake sorting workspace: left incoming list and All/Instructions/Images filters; wide centre email/document/attachment/evidence preview; right Create case candidate form with Principal, Registration, Work type, Due by, Instruction complete, Images complete, Hold, and Create for review. Suggestions must be distinct from confirmed values. Use CE-derived internal-app palette and restrained information density. No gradients, decorative charts, `Triage`, implementation language, or watermark.

## Concept 3

High-fidelity 16:9 case workspace for `QDOS26001`: charcoal navigation; header with registration, immutable principal/reference, work type, due date, Review, assigned engineer and Reopened; tabs Overview, Documents, Images, Report, Action history; instruction summary, completeness, next action, Box folder; right timeline, seven-day Chaser due with Copy message, case controls; Related Audit work includes `a.QDOS26001`; a reasoned Created in error replacement action is distinct from reopen. No delete action, gradients, decorative charts, implementation language, or watermark.

## Deferred-capability impact

The [UI planning impact register](README.md#deferred-capability-impact) applies to every generated concept. Prompts may show only current named workflows and stable evidence limits; they must not add placeholder mail automation, WhatsApp, EVA API, finance, deferred case types, guided capture, AI/vision, external accounts, malware controls or infrastructure language. Any later prompt revision follows an accepted owner/caller contract and must not be treated as product authority or operational evidence.
