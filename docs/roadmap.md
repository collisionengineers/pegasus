# Roadmap

Roadmap entries are outcome-level. Exact targets remain `unallocated` until
release planning assigns a Semantic Version. GitHub owns actionable work state;
an outcome here creates no issue, placeholder or dormant implementation.

## Now

- **Provider/intermediary instruction foundation — target
  `0.1.0-alpha.1`.** Publish the immutable provider-domain snapshot and prove
  each activated direct/intermediary route independently. Reference evidence is
  not route activation.
- **QDOS alpha workflow — target `0.1.0-alpha.1`.** Deliver every active QDOS
  case type through identity, accepted intake, immutable reference, Box
  custody, review/work management, exact manual EVA handoff, report evidence,
  observability/recovery and separate operator/management acceptance. The EVA
  handoff is deterministic UTF-8 JSON with the observed ordered 13 keys,
  selected custody-confirmed images and a SHA-256 manifest; it makes no EVA
  network call.
- **Request-scoped uploads — target `0.1.0-alpha.1`.** `INT-31` permits staff to
  generate temporary, revocable upload-only links without external accounts or
  a persistent portal. This orientation allocates the requirement; its token,
  limit, custody, retry and abuse contract still needs separate implementation
  acceptance.

## Next

- **Additional-provider activation — target `unallocated`.** Activate another
  provider only after its direct/intermediary evidence, policy and acceptance
  cohort pass through the shared workflow.
- **Provider-location evidence — target `unallocated`.** Activate `DATA-02`
  only after accepted source, schema/package, migration, caller and review
  behavior. Provider-domain data contains no locations/defaults/Case-ID maps.
- **Pairing readiness — target `unallocated`.** `INT-28` owns automatic
  instruction/image matching and `INT-32` owns separate half ages/chases and
  definitive ready notification.
- **Email workspace and provider APIs — target `unallocated`.** Extend
  categorisation across the approved mailboxes, provider-scoped APIs, general
  association, legacy DOC/MSG extraction, scan-like PDF OCR and typed
  post-report queries after their named blockers.

## Later

- **Engineer workbench and EVA replacement — target `unallocated`.** Transfer
  assignment, estimating, valuation and reporting independently; retain
  explicit Engineer acceptance and the manual handoff until each authority
  moves.
- **Deterministic reports and targeted sending — target `unallocated`.**
  Activate the Core render contract, assessment/Audit/diminution/addendum
  outputs and the separately gated original-thread/provider-API send.
- **Correspondence and accounts — target `unallocated`.** General authenticated
  email composition, query proposals, per-principal invoice inputs, accounts
  status and management measures require their own callers and permissions.
- **Send to AI — target `unallocated`.** `AI-09` is vendor-neutral,
  proposal-only and Engineer-reviewed. Imported AI source or staff MCP
  allocation does not activate it; no direct model API is in scope.
- **Conditional outcomes — target `unallocated`.** Guided capture,
  Tractable/Ravin and a custom domain remain retained problems without a caller,
  issue, resource or placeholder.

## Not planned

- External/customer accounts, public registration, staff MFA and mobile staff
  UI.
- Malware scanning, redaction, signatures, automated retention/deletion, legal
  hold, subject-request and dedicated compliance workflows.
- GitHub Actions deployment, separate QA/UAT/staging/training environments,
  slots/S1, private networking, zone/multi-region resilience and quarterly
  restore exercises.
- Predecessor import/operation/code reuse, SMS, Teams, a persistent customer
  portal and external-party accounts. `INT-31` upload-only links remain the
  explicit non-account exception.
