# Roadmap

Roadmap entries are outcome-level. Exact target releases remain `unallocated`
until release planning assigns a Semantic Version. GitHub owns actionable work
state; no issue is created merely because an outcome appears here.

## Now

- **Provider-specific classification foundation — target `unallocated`.** Resolve and prove the versioned Core-owned instruction policy through the local genuine-input evaluator. Activation requires accepted predicates/governance and caller-backed cohort evidence.
- **Live QDOS alpha workflow — target `unallocated`.** Deliver every active QDOS case type through staff identity, accepted intake, immutable references, Box custody, review/work management, EVA JSON/image handoff, exact report evidence, observability/recovery, and operator/management acceptance. Current source proves only the Development intake slice.

## Next

- **Additional provider activation — target `unallocated`.** Add a provider only through the same bounded Core workflow after provider reference/rule evidence and QDOS acceptance establish the shared path.
- **Email workspace and provider API beta — target `unallocated`.** Extend the accepted mailbox policy across four mailboxes, activate provider-scoped submissions/status, general association, legacy DOC/MSG extraction, scan-like PDF OCR, post-report work, and bounded image assistance after each named decision and dependency.

## Later

- **Expanded casework and automation — target `unallocated`.** Diminution, Commercial, automated WhatsApp/chasers, and individually activated AI assistance require their own contracts, callers, review, rollback, and acceptance.
- **EVA replacement and downstream engineering — target `unallocated`.** Direct EVA API use, assignment/engineering replacement, estimating, valuation, finance, automatic reports, and staff-selected AI Assessor activate only in their dependency order after vendor and product decisions.
- **Conditional outcomes — target `unallocated`.** Collision Engineers guided capture, Tractable/Ravin, and a custom domain remain retained problems with no caller, plan, issue, resource, or placeholder until a direct decision promotes them.

## Not planned

- External/customer application accounts, public registration, staff MFA, general in-app compose/reply/forward/send, and mobile staff UI.
- Malware scanning, redaction, signatures, automated retention/deletion, legal hold, subject-request, and dedicated DPIA/compliance workflows.
- GitHub Actions/OIDC deployment, separate QA/UAT/staging/training environments, slots/S1, private networking, zone/multi-region resilience, and quarterly restore exercises.
- Predecessor case/application import, predecessor operation after cutover, predecessor-code reuse, SMS, Teams, customer portal, and external-party accounts.

The [capability inventory](product/capabilities.md) owns all 213 stable IDs and
maps the retained old allocation evidence into these horizons. The
[delivery roadmap](plans/delivery-roadmap.md) remains the detailed dependency
route until bounded plans are converted or retired with claim parity.
