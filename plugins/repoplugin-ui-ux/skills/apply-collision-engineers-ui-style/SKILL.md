# Apply Collision Engineers UI Style

Use only after the UI's workflow and policy requirements are known. This is an internal-application style guide, not a copywriting, website, document, or imagery kit.

## Apply the style

- Start with the semantic tokens in [internal-app-style.md](references/internal-app-style.md). Preserve semantic names such as `surface`, `text`, `border`, `accent`, `danger`, and `focus`; do not encode policy in colour alone.
- Use the red gear logo from `assets/logo_no_margin.png` on light surfaces and `assets/web_logo_white.png` on dark surfaces. Do not redraw or alter it.
- Use the supplied Futura files only for restrained display/section labels. Keep operational body text and form controls on the system UI stack for legibility.
- Prefer dense-but-readable workflow screens: clear hierarchy, visible state, data-first content, modest borders, and a minimum 44px pointer target where practical. Do not conceal errors, warnings, or blocked states behind hover.
- Meet accessible contrast, visible keyboard focus, semantic HTML, labels/instructions, error association, logical tab order, and reduced-motion needs. Test narrow and wide layouts against the approved specification.

Read [migration-manifest.md](references/migration-manifest.md) before copying an asset. It is the complete approved asset list and scope boundary.

## Do not use this skill for

- public marketing/hero/CTA/WhatsApp/animation work;
- A4 documents, reports, letterhead, signatures, or correspondence;
- vehicle, case, report, correspondence, customer, or staff imagery;
- writing style, prescribed wording, other fonts, or unavailable skills.
