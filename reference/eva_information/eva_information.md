**EVA Information**

> Retained vendor reference evidence only (predecessor-era notes). The current
> accepted EVA integration is the manual 13-key JSON/image handoff owned by
> [requirements](../../docs/requirements.md) and
> [open decisions § EVA](../../docs/open-decisions.md); the vendor API text below is
> not the current specification and grants no permission to call EVA
> ([capabilities](../../docs/capabilities.md) allocates direct EVA API use to
> `0.7.0` as optional and non-blocking).



EVA is a case management system used by Collision Engineers, developed by Minotaur Software Ltd.



It is quite an old, esoteric system.

The long term aim would be full replacement of this system. In the interim, integration and working with this system will be required.

EVA does provide an API, however this is not currently being utilized as far as I am able to determine.

A vendor "Sentry" API guide was reviewed during predecessor planning; it documented GET report endpoints and POST token, instruction, claim update, note, and report submission endpoints, but no general claim-search or native batch endpoint. That guide is not retained in this repository and was never the current Pegasus specification; the retained vendor schema evidence lives under `reference/EVA/`.



Additionally, for small / helpful changes, they do seem to be open to assisting and working with us on this.



**Fields in EVA:**



Case/Po - Our reference. This is manually created by an admin worker during addition to EVA. 



Claim no - "Their" ref - ie the work providers reference



Principal - An internal code that Collision Engineers Use for work providers



Type - Outcome of the inspection. If this is blank, the Engineer has not completed this.



Released - This is a date field. This contains a date that the report is sent to the client, if the Engineer has completed the assessment.

## Consolidated Engineer information map

The future `UI-15` workbench arranges progressive sections for:

1. inspection, contact, address, circumstances, instructions and notes;
2. vehicle identity, specification, condition, modifications, history and
   roadworthiness;
3. impact zones/severity, tyres/belts, unrelated damage and material transfer;
4. versioned estimate lines, source, versions and totals;
5. repairer, original-versus-assessed values, savings and contract repair;
6. valuation evidence, Engineer acceptance, adjustments and revaluation;
7. accepted report-summary inputs and computed-once figures;
8. photos, screenshots, documents and source custody;
9. salvage, recovery, storage, retention and movement;
10. report text; and
11. report, fee note, authority, total-loss, salvage-letter and notification
    actions.

`UI-15` owns arrangement only. Existing case, document, `ENG-*`, `RPT-*`,
`EXT-*`, `MAIL-*` and accounting owners retain their data, decisions and
effects.
