# Research — INTK-016 upload confirmation decision

All premises below verified by read-only checks against the task worktree at `origin/dev` (0449e6ec) unless marked assumed.

## What exists (verified)

- **Outcome surface**: `src/Pegasus.Web/Presentation/UploadOutcome.cs` — `UploadOutcomeQueries.BuildAsync` builds one `UploadOutcomeView` per member; kinds `{Working, Attached, ImageCaseRegistered, NeedsReview, PossibleMatch, ReadyToCreate, CannotBecomeCase, Failed}`. Rendered by `Shared/_UploadOutcome.cshtml` from both `UploadStatus.cshtml` (single-file upload; `Upload.cshtml.cs:141-151` keeps one-member groups on that page) and `UploadGroupStatus.cshtml` (multi-file). Post-INTK-015 `UploadGroupStatusModel` collapses an all-identical `ImageCaseRegistered` set into one `GroupRegistrationOutcome` reported once for the group.
- **Case search Core query**: `ISearchCases` (`src/Pegasus.Core/Cases/CaseQueries.cs:111`) — `SearchCasesQuery(Actor, CaseSearchFilters, Page, PageSize)`; requires `StaffAccessRight.PerformCasework`; `CaseSearchFilters.Query` is the free-text filter (`EfCaseQueryStore.cs:24-32` matches reference, compacted registration, principal, claimant…). Result items carry `CaseId, Reference, State, Registration, Claimant` — everything the suggestion list needs; **no case Version** (read via `IGetCase` → `CaseDetails.Workflow.Version`).
- **Staff attach path**: `ILinkIntake` (`DurableIntake.cs:1117`) — `LinkIntakeRequest(ReceiptId, CaseId, ExpectedIntakeVersion, ExpectedCaseVersion, EditLeaseToken, Actor, OperationKey, Reason)`; requires `PerformCasework`, a reason, an operation key (≤100 chars), and a **case edit lease** (`IAcquireCaseEditLease`, `ClaimCaseEditLeaseRequest(CaseId, ExpectedVersion, Actor, OperationKey)`). `LinkIntake.ExecuteAsync` itself calls `IImageIntakeCasePairing.SyncMergeAfterLinkAsync` — so one call is the staff-directed variant for **both** instruction documents and image groups: for an ImageIntake-registered receipt the merge transition (INTK-008 pairing owner) runs automatically after the link, replay-safe on a deterministic per-receipt merge key.
- **Manual-vs-automatic provenance**: `IntakeReceipt.ManualLinkedCaseId/ManualAssociationVersion` distinguish a staff link from the automatic `AcceptedCaseId`; `CurrentCaseId`/`CurrentCaseReference` merge the two.
- **Existing manual link UI**: `/Received/{id}` (`Pages/Intake/Details`) — operator must hand-type the case GUID and version, claim the lease as a separate step, then link. Works but is exactly the surface the operator complained about having to reach blind; it also shows raw GUIDs (pre-dates the ban).
- **JS conventions**: `wwwroot/js/site.js` is progressive-enhancement-only (page works without script), attribute-driven (`data-auto-refresh`, `data-dropzone`, `data-dialog-open`…), CSP `default-src 'self'` (no inline script). No existing autocomplete/combobox anywhere in the app (grep) — this is the first; ARIA roles are added by script so the no-script markup stays honest.
- **Tests**: `tests/Pegasus.IntegrationTests` — `IntakeWebApplicationFactory` (+ `useIntegrationTestAuthentication: true` gives header-driven anonymous via `X-Test-Anonymous`), `IntakeWebDriver` (upload + `ProcessQueuedAsync` drains worker), `UploadOutcomeQueriesTests.cs`, `GroupedIntakeWebTests.cs`, `Browser/AccessibilityTests.cs` (axe + no-inline-style + landmark rules), `Browser/UploadRowsBrowserTests.cs`.

## Decisions

1. **Where the staff decision appears**: `ReadyToCreate`, `PossibleMatch`, and `ImageCaseRegistered` outcomes gain an "Add to an existing case" offer plus "Cancel". `ImageCaseRegistered` keeps its report-first shape (automation at the accepted bar is reported, not re-offered — INTK-010 rule): the registration report stays the outcome; adding to a case is offered as the staff-directed merge the operator described. `Attached` stays a pure report. `NeedsReview` keeps routing to the Unidentified surface (INTK-018 owns that decision).
2. **Endpoint**: a JSON GET page handler `OnGetCaseSearchAsync(term)` and a POST handler `OnPostAttachAsync(...)` on **both** status page models, each a thin call into one shared presentation service (`UploadCaseDecision` beside `UploadOutcomeQueries`) so there is exactly one implementation (one Core owner rule). Page `[Authorize]` + Core `PerformCasework` enforce authorisation; anonymous GET redirects to sign-in.
3. **Attach orchestration** (shared service): short-circuit if the receipt is already linked to the chosen case (replay safety at flow level); read case version via `IGetCase`; `IAcquireCaseEditLease` with deterministic key `upload-attach-lease:{receiptId:N}:{caseId:N}`; `ILinkIntake` with deterministic key `upload-attach:{receiptId:N}:{caseId:N}` and the operator's typed reason (required, per the Intake/Details convention). Recoverable failures fail closed to an honest error message; nothing silent.
4. **No-script fallback**: the attach form works without JS — the visible input accepts a typed case reference, resolved server-side to exactly one case via `ISearchCases` (exact reference match); ambiguity or no match fails closed with an error. Script upgrades the same input to a debounced fetch combobox (role added by JS).
5. **Attached copy honesty**: with a staff (`ManualAssociationVersion != null`) link the Attached report must not claim "automatically". The branch keys on `status.CaseId ?? receipt.CurrentCaseId` and words the two provenances differently.
6. **Cancel**: a plain link back to `/Upload` — no mutation; material retained; the status page remains reachable and honest.

## Assumed (not independently verified)

- `AcquireCaseEditLease` re-issue semantics on an exact operation-key replay — mitigated by the already-linked short-circuit before any lease attempt.
- `QueuedIntakeStatus.CaseId` may not reflect a later manual link (it is written at processing time); mitigated by also consulting `receipt.CurrentCaseId` (checked in implementation).
