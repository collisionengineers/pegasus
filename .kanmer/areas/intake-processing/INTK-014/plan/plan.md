# INTK-014 plan

Branch `task/intk-014-image-case-box`, worktree `../pegasus-worktrees/intk-014` (origin/dev 0449e6ec). One PR to `dev`.

## Steps

1. **Core ports and kinds.** Add `ExternalWorkKinds.CreateImageCaseCustody`/`MergeImageCaseCustody` and route them to the custody handler in `ProcessQueuedExternalWork` (reuses the existing typed dispatch — no new pipeline). Extend `ICaseCustody` with `RetainImageCaseAssetAsync(root, source, ordinal, operationKey[, leaseGuard])` and `MergeImageCaseContentsAsync(imageRoot, caseRoot, operationKey[, leaseGuard])`; defaults throw `NotSupportedException` so every existing implementation/fake keeps compiling and fails closed (same default-method pattern the interface already uses for lease overloads).
2. **Schema.** Migration `ImageCaseCustody`: `ExternalWorkItems.CaseId` → nullable + new nullable `ImageIntakeId` (FK ImageIntakes, Restrict, indexed); `ImageIntakes` + `CustodyState`, `CustodyRootRemoteId`, `CustodyConfirmedAtUtc`, `CustodyMergedAtUtc` (all nullable). No new table → `scripts/Test-MigrationGrants.ps1` needs no census entry; run it to prove.
3. **Enqueue on registration.** In `EfImageIntakeStore.RegisterAsync`'s existing transaction, insert the create work row (Kind `create_image_case_custody`, `ImageIntakeId`, `OperationKey $"image-case-custody:{intakeId:N}"`, `State pending`, `CaseRootCreationToken = CustodyCreationOwner.Create()`) and set `CustodyState='pending'` — exact mirror of `EfCaseAcceptanceStore.AcceptAsync`'s enqueue. Replay paths (operation-key replay, group replay, identity replay) never enqueue twice because they return before the insert.
4. **Enqueue on merge.** In `EfImageIntakeStore.TransitionAsync`, in the merge branch only, insert the merge work row (Kind `merge_image_case_custody`, `ImageIntakeId`, the merged-into `CaseId` so the row joins the Operations page, `OperationKey $"image-case-custody-merge:{intakeId:N}"`). Operation-key replay of the transition returns early, so no duplicate enqueue; the work-row OperationKey unique index is the backstop.
5. **Processor.** Extend `EfQueuedCustodyProcessor`: claim logic unchanged (reuses the CAS claim loop); new image payload loaders. Create: resolve group member receipts exactly as `EfImageIntakeStore.RegisterGroupMemberReceiptsAsync` resolves them (members → latest evaluation → processed receipt), keep receipts whose decision is `image_intake_registered`, order by member ordinal (origin first for non-group), load each `source` asset row; `CreateCaseRootAsync(imageIntakeId, imageReference, token, key)` (reuse — the image folder IS a bound root) then `RetainImageCaseAssetAsync` per image; completion transaction stamps `CustodyRootRemoteId`, `CustodyState='confirmed'`, `CustodyConfirmedAtUtc` under the processing lease. Merge: require the create side done (`CustodyState='confirmed'` or root id present; otherwise throw retryable `IOException`-mapped failure), resolve both roots via `GetExistingCaseRootAsync`, call `MergeImageCaseContentsAsync`, completion stamps `CustodyState='merged'`, `CustodyMergedAtUtc` and adds a `CaseHistory` `image_custody_merged` row (mirrors `custody_confirmed` convention).
6. **Box adapter.** `BoxContentClient`: extract the child-paging loop shared with `FindChildAsync` into `ListChildrenAsync`; add `MoveFileAsync` (PUT `files/{id}` parent+name, fenced on file and destination) and `DeleteFolderAsync` (DELETE `folders/{id}`, non-recursive — a non-empty folder fails closed; 404 treated as done). `BoxCaseCustody.RetainImageCaseAssetAsync`: hash+length verify from `IIntakeArtifactStore` (same checks as `RetainAcceptedIntakeSourceAsync`), file name `{ordinal:000} {SafeName(fileName)}`, idempotent by find-then-verify-bytes. `MergeImageCaseContentsAsync`: validate both roots, get-or-create `Evidence/Images` under case root, move every non-binding file (name-conflict: verify same content and skip — replay; different content: prefix with the image reference), delete the binding file, delete the emptied folder.
7. **Local adapter.** `LocalCaseCustody`: images under `{imageRoot}/images/{ordinal:000}-{hash}` (content + metadata, reusing `CreateOrVerifyContentAsync`/`CreateOrValidateJsonAsync`); merge moves the `images` tree under `{caseRoot}/images/`, removes the image root directory. Same fail-closed root resolution via `Resolve`.
8. **Failure honesty + retry.** `EfExternalWorkStore.FailProcessingAsync`/`MarkPoisonedAsync`: image-kind branches — completed-effect replay check (root already stamped ⇒ complete), else `custody_dependency_failure` under the attempt cap re-arms `pending` with backoff (vehicle-lookup convention: delays 1m/5m/15m/1h/6h, cap 6); otherwise terminal `failed` + `CustodyState='failed'`. `Include(item => item.Case)` and the workflow lookup tolerate null CaseId. Registration and merge themselves are never blocked: they only insert a queue row.
9. **Nullable CaseId fallout.** Fix compile sites (`EfOperationsStore` join cast, `EfQueuedCustodyProcessor`/`EfVehicleLookupWorkStore` CaseId dereferences guarded by kind) — behaviour unchanged for case kinds.
10. **Tests.** Extend `StatefulBox` (settable parent, PUT file move, DELETE folder-only-when-empty/file) + Box adapter tests: image asset upload idempotency, merge move+remove, refusal outside the root, non-empty-folder delete refusal. Integration tests with `LocalCaseCustody` + real EF store: register(group) enqueues one create work and processing confirms custody columns; merge enqueues move work and processing folds the folder; failing custody adapter → work re-arms then terminally fails with `CustodyState='failed'` while `IntakeAssets`/blob rows are untouched (images never lost); replay safety (double process = one effect).
11. **Verification.** `dotnet build -c Release` (zero warnings), focused `dotnet test` filters (custody + image intake), `scripts/Test-MigrationGrants.ps1`, `scripts/Test-AzureDeploymentPlan.ps1 -Mode Local`. Simplification pass over the branch diff before the PR.

## Acceptance
- Registering an image-initiated case (group or single) durably enqueues Box work that creates `{reference}` under the approved root and uploads every group image; remote root id + state recorded on ImageIntakes.
- Merge enqueues Box work that moves contents into the paired case's root (`Evidence/Images`) and removes the emptied folder.
- No Box outage can block registration or merge or lose an image; failures are recorded and retryable.
- Production verification of the real Box path is deploy-stage (ticket Verification checklist) — not claimable from this task.
