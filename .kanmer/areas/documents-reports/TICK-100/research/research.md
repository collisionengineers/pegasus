# Research — addendum rendering

## Question

Is addendum rendering part of the approved initial activation?

## Findings

1. FRD-11 already requires corrections/addenda to create a new reasoned immutable version retaining earlier artifacts/facts/actor/time/source; no silent overwrite.
2. The workspace has an `addendum-report` template, but rendererref1 approved evidence covers assessment variants and fee note only.
3. RPT-05 still lacks accepted amendment input identity, exact layout/wording, approval, recovery, and caller evidence. The operator approved leaving unsupported catalogue entries inactive.
4. DOCS-001/SIMPLI-014 must nevertheless design report identities and storage so corrections/new versions are possible without rework; that shared versioning does not activate the addendum template.
5. The generic workspace addendum cannot become product behavior solely because it exists.

## Implications

- Do not migrate/activate the workspace addendum template in the initial caller.
- Implement immutable base report identity/version/hash/provenance and correction-safe storage now.
- Keep RPT-05 deferred until amendment behavior/template/caller are accepted.
