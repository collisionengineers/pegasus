## What

Give the inspection date and the vehicle mileage real EVA instruction fields,
instead of the labelled note lines [[TICK-077]] sends them as today.

## Why

EVA's `Instruction/Inspection` request model documents no inspection-date
field and no mileage field. Both are values Pegasus holds and an assessor
needs, so [[TICK-077]] sends them inside `NotesStr` as labelled lines:

```
Work Provider: Connexus
Inspection Date: 10/02/2026
Mileage: 43850 Miles
```

Nothing is dropped, but a note is free text — EVA cannot index, validate or
report on it the way it could a typed field. Deferred at the operator's
direction, 2026-08-27.

The work provider is on that list for a different reason: it was displaced
from `InsName` when the operator directed that field carry the claimant name.
Whether it belongs in `PrincipalName` is worth settling here too — Pegasus
calls the work provider the Principal, so the names line up, but no accepted
source establishes that mapping and [[TICK-077]] deliberately refused to guess
it.

## Approach

- Ask Minotaur whether the instruction model can carry an inspection date and
  a mileage with its unit. Their `Claim/Update` documentation states the model
  "can be extended to include additional fields on request", so an extension
  is a supported conversation rather than a change request against a frozen
  contract.
- Settle whether `PrincipalName` is the right home for the work provider.
- On confirmation, move each value from `CaseEvaApiMapping.NotedFields` to a
  real payload field and extend `EvaApiMappingTests` to pin it.
- Bump `CaseEvaApiMapping.MappingVersion`, since what a submission means will
  have changed.

## Verification

- [ ] EVA has confirmed a field for each value, or has declined and the note
      is recorded as the settled answer.
- [ ] Any confirmed field is mapped, tested, and proved by one live test
      submission.
- [ ] `docs/frd/frd-07-eva-and-external-engineering-handoff.md` reflects
      whichever answer is settled.
