## What

`src/Pegasus.Web/Pages/Operations/Index.cshtml.cs:427` still names the retired
page as the review target for a Draft-ready Estimate AI job:

```csharp
AiJobKind.Estimate =>
    (OperatorLabels.AiJobs.ReviewEstimate, "/Cases/Assessment/Index"),
```

`Operations/Index.cshtml:104` renders it as
`<a asp-page="@recordRoute" asp-route-id="@subjectId">`, so pressing "Review
estimate" issues `GET /Cases/{id}/Assessment`, which [[ENG-034]] turned into a
301 to `/Cases/{id}?section=estimate`. The operator still lands in the right
place — this is exactly what the permanent redirect is for — but it is the
last direct in-app reference to a retired route and will rot.

## Fix

Point the tuple at `"/Cases/Details"` and add `asp-route-section="estimate"`
to the anchor so the link goes straight to the Estimate section with no
redirect hop. Check whether any Operations test asserts the old href.

## Why it was not fixed in ENG-034

`src/Pegasus.Web/Pages/Operations/*` is outside ENG-034's owned paths (its plan
and files documents name only the Case page, the Assessment page, the operator
labels and the Test UI catalogue), and the repository's scope rule forbids
"while I'm here" edits. Raised by the ENG-034 round-six review as a deferred
nit; nothing is broken today.
