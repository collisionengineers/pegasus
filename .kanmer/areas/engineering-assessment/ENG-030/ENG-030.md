## What

Own the **Audatex direct estimating-service link** — the record-bar control on
the Assessment page that opens the case in the Audatex estimating service. It
is distinct from the live Audatex **PDF import** ([[ENG-002]] / EXT-12), which
is delivered and is not in question here.

Two acceptable outcomes, and the ticket must land on one of them:

1. Wire the link to a real, enabled destination once the estimating-service
   arrangement exists; or
2. Record the operator decision to drop the capability and **remove** the
   control, per PLAT-015's "absent, not disabled" rule.

What is not acceptable is the status quo: a permanently inert button that no
deployed state can enable.

## Why

D21 (`.kanmer/groups/EPIC-011/decisions-2026-08-29-done-rule.md`) settled that
a permanently inert D7 seam is never a delivered capability, and D22 settled
that it still *renders* as a disabled button. [[ENG-025]]'s own `## What` names
the seam ("record bar … Glass's/Audatex disabled seams per D7") and its
Verification box reads "No inert control remains" — so ENG-025 was reversed out
of Done and cannot return while it owns an unowned inert control.

The Glass's half already has an owner: [[TICK-085]] ("Complete Glass's
repair-estimate import from a representative export"), blocked on obtaining a
representative Glass's export. **The Audatex direct link has no board ticket at
all** — the adjudication greps over `.kanmer/areas` for "Audatex" returned
ENG-002 / ENG-025 / ENG-026 / [[ENG-028]] / TICK-085 / TICK-093 / [[CASE-012]] /
PLAT-015 / UIIMP-007 / UIIMP-012, every one of which concerns the PDF or JSON
*import* path, never an "Open in Audatex" direct link. PLAT-015 (archived)
named the inert "Open in Glass's/Audatex" spans as placeholders to remove, not
to wire.

Evidence recorded by the audit on merged `dev` at `b92cb9a7`:

- `src/Pegasus.Web/Pages/Cases/Assessment/Index.cshtml:214` —
  `<button type="button" class="btn" disabled aria-disabled="true">Audatex</button>`
- `src/Pegasus.Web/Pages/Cases/Assessment/Index.cshtml.cs:193-194` —
  `public string EstimatingServiceCondition => "Available once the
  estimating-service link is agreed";` — a hard-coded literal with no runtime
  input and no `@if` enabling branch, so no state of the deployed system
  renders the control enabled.
- The sibling `Glass's` control at `Index.cshtml:211` has the same shape and is
  owned by TICK-085.

## Approach

- Establish the fact first, read-only: does a direct Audatex estimating-service
  link exist for Collision Engineers, and on what terms? A live integration is
  a `requires-live-approval` write and needs explicit per-target approval.
- If it exists, reuse the existing record-bar control and the `.gated` /
  `data-condition` convention (D22) — replace the hard-coded literal with a
  real computed condition so the control renders enabled when the condition is
  met, which is D21's legitimate "conditionally disabled" row.
- If it does not, remove the control and the `EstimatingServiceCondition`
  property from `Pages/Cases/Assessment/Index.cshtml(.cs)` and record the
  decision in the EPIC-011 decisions file. Coordinate with [[ENG-028]], which
  owns `Pages/Cases/Assessment/**` in wave 4.
- Do not introduce a feature gate to hold the capability open: a closed gate is
  a D21 "No" row and would not release ENG-025 either.

## Verification

- [ ] Either the Audatex control posts to a real destination and is enabled in

- [ ] `grep -n "disabled" src/Pegasus.Web/Pages/Cases/Assessment/Index.cshtml`
      shows no permanently inert control, only conditions that can clear.
- [ ] `EstimatingServiceCondition` is either a computed value or gone.
- [ ] The outcome is recorded in
      `.kanmer/groups/EPIC-011/decisions-2026-08-29-done-rule.md` or its
      successor, so ENG-025's Verification box can be discharged honestly.
