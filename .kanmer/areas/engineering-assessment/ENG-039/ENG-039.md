## What

In `src/Pegasus.Web/Pages/Cases/Shared/_CaseEstimate.cshtml` the local
function call `RenderEstimateTotals(totals);` sits inside markup context
(lines 255 and 272, both inside `<div class="estimate-bottom">`), so Razor
emits it as **literal text** instead of calling it. The estimate totals table
(Parts, Labour, Paint, Other, Subtotal, VAT, Total) never renders in either
the editable or the read-only branch, and the operator sees the raw source
text `RenderEstimateTotals(totals);` where the totals should be.

The sibling call `RenderSpecificationLines(estimate!, ...)` on line 274 sits
in code context and works correctly, which is why the defect is easy to miss.

## Evidence

Proven against the compiled assembly at ENG-034's head
(`795506d75`, `src/Pegasus.Web/bin/Release/net10.0/Pegasus.Web.dll`): the exact
UTF-16 literal `RenderEstimateTotals(totals);` appears twice in the string
heap, wrapped in the surrounding `</div>` / `</div>` markup chunks, while
genuine code lines from the same file (`var caseId = Model.Case!...`,
`RenderSpecificationLines(estimate!`) appear zero times — the assembly does not
embed source, so the only way that text is in the binary is as emitted markup.

## Pre-existing, not an ENG-034 regression

Identical on `origin/dev` in the retired page,
`src/Pegasus.Web/Pages/Cases/Assessment/Index.cshtml` lines 524 and 541.
[[ENG-034]] moved the markup verbatim under its "move, do not rewrite" rule, so
it carried the defect over rather than introducing it. Raised as a follow-up by
the ENG-034 review rather than fixed in that PR (scope rule 1).

## Fix

Wrap both calls so Razor parses them as code (`@{ RenderEstimateTotals(totals); }`),
and add an assertion that the totals table renders — no test currently asserts
any totals figure appears in the rendered HTML, which is why this survived.
`CaseEngineerSectionsWebTests` renders an estimate and is the natural home.
