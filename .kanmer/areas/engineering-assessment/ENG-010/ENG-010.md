## Why

The operator confirmed QDOS26008's vehicle has MOT history, yet the case shows no calculated mileage.

**Root cause.** `VehicleMileagePolicy.Calculate` does run and its result is persisted on the vehicle lookup observation (`EfVehicleLookupWorkStore`), but its only consumer is the Assessment page prefill (`Cases/Assessment/Index.cshtml.cs:97-160`). `CaseDataSnapshotFactory` writes mileage solely from `draft.VehicleMileage` — the extraction path — so the case itself never receives the MOT-derived value.

## Evidence step first

Before designing: read production for QDOS26008's `VehicleLookupRequests` / `VehicleLookupObservations` rows and confirm the MOT tests and calculated mileage are actually present. If the lookup never ran, that is a different defect and this ticket re-scopes to it.

## How to verify

Production SQL readback of the observation, then the case overview showing the value labelled as external MOT evidence with its observation date. Must not overwrite an extracted or staff-supplied value.
