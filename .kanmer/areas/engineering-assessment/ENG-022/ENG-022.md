## What

`infra/main.parameters.json` gained a UTF-8 BOM in [[TICK-077]] (`09beefef`).
`azd provision` reads that file with a Go JSON parser, which refuses a BOM:

```
ERROR: deployment failed: initializing provisioning manager: resolving bicep
parameters file: error unmarshalling Bicep template parameters: invalid
character 'ï' looking for beginning of value
```

Remove the three bytes. No content change.

## Why

It blocks every release. Found while releasing `09beefef`: promotion, artifact
build and the ACR push all succeeded, and provisioning failed at its first step.
Nothing was deployed, so production continued to serve release 35 unmodified.

No CI gate reads this file as JSON — `Test-AzureDeploymentPlan` matches it as
text — so nothing caught it. TICK-077 added a BOM to forty files; the other
thirty-nine are C#, Markdown and bicep, all of which tolerate one. Only this
file is parsed by something that does not, and only this file is in scope.

## Verification

- [ ] `infra/main.parameters.json` starts with `{`, not `EF BB BF`.
- [ ] Its content is otherwise byte-identical.
- [ ] `azd provision` gets past `Initialize bicep provider`.
