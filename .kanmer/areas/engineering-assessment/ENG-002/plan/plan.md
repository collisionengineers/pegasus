# ENG-002 plan — drag-and-drop Audatex estimate import + specification visibility

Scope decision (honest for this release): deliver the **drag-and-drop route end to end for the Audatex full-report PDF** (the one external format the corpus evidences), the provenance rules, and draft/accept visibility on the assessment page. The MCP route already works and is cited, not rebuilt. Glass's parser parked (no sample). EXT-09's cost derivation is not settled: report "Repair cost figures" readiness continues to fire.

Fail-closed rules carried throughout: wrong money is worse than no money — any parse ambiguity or checksum mismatch rejects the whole import with an honest message; no partial or silent line drops; the original file is retained in the case-document custody boundary whenever any line lands.

## Steps

1. **Core contract** (`EstimateImport.cs`): `IEstimateDocumentParser { RepairSpecificationSourceRoute Route; bool CanParse(fileName, mediaType); ParsedEstimate Parse(ReadOnlyMemory<byte>); }`, `ParsedEstimate(string SourceVersion, IReadOnlyList<EstimateLineInput> Lines)`, `EstimateParseRejectedException(reason)`. Reuses `EstimateLineInput` and `RepairSpecificationSourceRoute`; the port is the external boundary in front of PdfPig (same shape of split as `IIntakeSourceReader` / `MimeKitPdfPigOpenXmlIntakeSourceReader`).
2. **Audatex parser** (Infrastructure, PdfPig): per page, group words into baseline rows; section state machine keyed on the printed headers; pair each right-column numeric row to exactly one description row (baseline distance < half row pitch; two candidates ⇒ reject). Line mapping (deterministic, documented in-code): LABOUR rows → `repair` when the description starts "REPAIR", `check_labour` when it starts "CHECK", else `rnr`, with WorkUnits; PAINT WORK rows → `paint_new`/`paint_repair`/`paint_blend`/`paint_prep` by the printed operation words, WorkUnits; PARTS rows → `new_part` with Price, PartNumber, Betterment (missing price cell ⇒ `Unpriced = true`); Extras rows → `specialist_fixed` with Price. Description-only rows are continuation text appended to the preceding line's description. Status `provisional` on every imported line. Checksums (all must hold or the import is rejected naming the failing section): labour WU sum == printed Total Work Units; paint WU sum == printed paint total; priced parts sum == printed parts Sub Total; extras sum == printed Total Extras. Header `Assessment Number` + `Version` required → `SourceVersion`.
3. **Import handler** (`OnPostImportEstimateAsync(id, operationKey, reason, upload)`): actor must be staff Engineer (checked first, before any mutation — `StartDraftAsync` would refuse anyway but the document must not be retained for a refused import); file ≤ 10 MiB, parser `CanParse` else honest refusal. Order: **parse first (no side effects)** → on rejection nothing is retained and the message states why. Then, with parse in hand: read case, refuse when a current draft exists (recovery for a wrong draft is the existing line-replacing assessment save); when an accepted specification exists require the reason field and supersede it. Mutations: acquire lease (fresh op key) → `IAddCaseDocument` (role `Other`, `StaffUpload`, identity `estimate-import:{opKey}`) → acquire lease again at version+1 → `StartDraftAsync` with `Source(AudatexPdf, ArtifactReference: estimate-import:{opKey}, SourceVersion: parsed, Sha256: retained version's hash)` + parsed lines + op key. TempData status names lines imported and that the original document is kept on the case.
4. **Accept handler** (`OnPostAcceptSpecificationAsync`): Engineer types the five money buckets, VAT and VAT-registered flag from the retained original (no derivation, no prefill — EXT-09 owns any formula); acquire lease → `AcceptAsync` with the draft's own Source and the typed basis; `RepairSpecificationPolicy` enforces internal consistency and Engineer authority. Legacy (`LegacyUnresolved`) drafts refuse acceptance with the store's own message.
5. **Razor** (estimate tab): import form (file input with the existing dropzone drag-drop affordance), current-specification panel — state, version, operator-friendly route label ("Imported from Audatex", "Manual", "AI proposal"), ordered lines table (type, description, work units, price, part number, betterment), accepted panel shows basis totals. No GUIDs, no banned operator terms; consequence guidance one sentence.
6. **DI**: register `AudatexEstimatePdfParser` as `IEstimateDocumentParser` (scoped, beside `IRepairSpecificationStore`).
7. **Tests**: parser fixture tests (synthetic PdfPig-built PDFs — happy path with exact expected lines and money, checksum mismatch, ambiguous baseline, missing header, unpriced part); web tests for import (draft lands with route/sha/lines; refused for non-Engineer; refused on existing draft; original retained as case document) and accept (basis persisted, state Accepted). Local-only manual verification: run the parser against the real corpus sample in the scratchpad harness and record *that* it parses with totals matching the document (no corpus values in repo or board docs).
8. **Verification**: `dotnet restore ./Pegasus.slnx`, `dotnet build ./Pegasus.slnx -c Release --no-restore` (zero warnings), focused `dotnet test` filters for the new test classes plus `RepairSpecification*` and `AutomationAssessmentIngressTests`.
