## What

Give Pegasus a way to receive a repair estimate, so that estimate lines and their money reach a case without anyone typing them.

The operator named three routes on 2026-08-19, verbatim:

> "these are imported through other means generally ie external estimating systems: auxatex, glasses etc. Or an AI performs an estimate and sends via MCP connector. We also need to be able to drag+drop an estimate in"

So: **external estimating systems** (Audatex, Glass's), an **AI-produced estimate delivered through the MCP connector**, and **drag-and-drop of an estimate file** by staff.

## Why

This is the missing input that blocks report generation end to end. [[DELIV-012]] delivered the report-draft entry point on the case assessment page and it is reachable, but `AssessmentReportSnapshot.Validate()` requires labour hours, an hourly rate, parts, paint materials and specialist/other, and none of those is persisted today — `rates.card`/`rates.class` are free text, and `HourlyRate` exists only inside the report contract. The button therefore lists "Repair cost figures" as outstanding for every real case. No figures were invented, because wrong money in an engineering report is worse than no report.

The landing place already exists: `EstimateLineInput` / `CaseEstimateLineRecord` (`src/Pegasus.Core/Assessment/AssessmentContracts.cs`) carry `Type`, `GuideCode`, `Description`, `WorkUnits`, `Price`, `Unpriced`, `PartNumber`, `Betterment`, `Status`, evidence and justification, and [[TICK-093]] now versions them under a repair specification with route provenance. What is missing is the way in.

## Scope questions to settle before implementing

- Which formats each external system actually produces, and whether Pegasus parses them or receives an already-structured payload. Do not assume a format — get real examples first.
- How an imported estimate maps to the report's cost buckets (labour hours × rate, parts, paint materials, specialist/other). That derivation is **EXT-09's** authority — `docs/capabilities.md` records that its "formulas and permissions require accepted authority" — so this ticket must not settle it unilaterally.
- Provenance and trust: an imported or AI-produced estimate is not a confirmed engineering finding. Existing precedent is that automation values land unconfirmed for review (MCP-06), and confirmation stays staff-Engineer-only; imported lines should follow the same rule.
- Whether drag-and-drop reuses the existing upload/custody path rather than introducing a second intake route.

## Verification

Lines land provisional in a draft; Engineer acceptance confirms them.)*
- [x] An MCP-delivered estimate lands unconfirmed and requires staff-Engineer confirmation. *(Pre-existing `pegasus_assessment_update` route, covered by `AutomationAssessmentIngressTests`; specification acceptance is Engineer-only and refuses unconfirmed lines.)*
- [x] Drag-and-drop reuses the existing custody boundary; the original file is retained as received. *(`IAddCaseDocument` / `DocumentSource.StaffUpload`, the case-document custody path; the draft's provenance carries the retained file's SHA-256.)*
- [ ] With an imported estimate present, the report-draft entry point's readiness no longer names "Repair cost figures" and produces a report. *(Deliberately NOT delivered: `ReportRepairCosts` is hours × rate plus its own VAT rule, and that derivation is EXT-09's authority. What EXT-09 now inherits: an Engineer-accepted `RepairCalculationBasis` per specification plus full imported line data.)*
