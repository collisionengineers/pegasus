## What

Create a capability inventory entry, supplier contract, and accepted ADR for the Experian AutoCheck vehicle-history check shown as unbound markup in the Case Details and Assessment screens.

## Why

The Claude Design prototypes show an Experian AutoCheck vehicle-history check on both the case details and assessment screens. [[PLAT-001]] shipped this as inactive unbound markup because it has no capability ID in `docs/capabilities.md` at all — it is not in the inventory. Before it is more than markup it needs an inventory entry, a supplier contract, and an accepted ADR. The open-questions doc in [[PLAT-001]] records this under "Parked (explicitly deferred)".

## Approach

- Add a capability ID (e.g. `EXT-14`) to `docs/capabilities.md` with allocation `Later` and a target release.
- Record the supplier (Experian) and the contract/terms requirement.
- Write an ADR for the integration boundary (read-only history check, no case state mutation, cached result with provenance).
- Wire the unbound markup to a real handler once the contract is accepted.

## Verification

- [ ] Capability ID exists in `docs/capabilities.md` with allocation and owner FRD.
- [ ] ADR accepted and linked from the capability row.
- [ ] The unbound markup in `Details.cshtml` and `Assessment/Index.cshtml` carries the capability ID in its Razor comment.
