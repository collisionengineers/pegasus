## What

The operator Export produces a zip of the 13-key JSON and `Images/` only, with
the JSON indented. `provenance.json` and `manifest.sha256` stop travelling in it.

## Why

Exporting `ap.QDOS26015` produced a package EVA will not import. Three
independent known-good samples agree with each other and differ from ours:
`reference/eva_information/AX_SP58WVO.json`,
`reference/eva_information/Final Format Example 02.json`, and the operator's
`docs/json-extraction-parity/ap.QDOS26015/old-extraction-working/QDOS_NX14AXY.json`.
All three are 2-space indented and carry no companion files. Ours is minified
and carries two.

Operator direction (2026-08-24): neither `manifest.sha256` nor `provenance.json`
needs to be in the export.

The key set and key order are already correct — this ticket does not touch them.

**The constraint.** `EvaBundleSchema.CreateOfflineReplay`
(`src/Pegasus.Core/Eva/EvaBundleSchema.cs:578`) is the single writer for two
different products: this operator export ([[CASE-019]]) and the gated FRD-07
hand-off. FRD-07 mandates the manifest for the hand-off, and
`docs/operator-notes.md:505` (protected) calls it "a reviewed JSON/image/manifest
download". So the manifest stays on the hand-off and goes from the export — the
writer has to tell the two packagings apart. Blocked by the doc amendment.

Nothing in `src/` reads either file: no importer, no verifier, no UI, no script.

## Approach

- `WriteArchive` (`:851`) — emit `provenance.json` and `manifest.sha256` only for
  the hand-off packaging. One enum threaded through `CreateOfflineReplay`, one
  switch, one list.
- `WriteOrderedJson` (`:756`) — `Indented = false` to `true`, for both
  packagings. `Utf8JsonWriter` indents 2 spaces by default. FRD-07 does not
  constrain indentation, and one JSON writer beats two.
- Leave `provenance.json`'s own `Indented = false` (`:778`) alone — it is internal.
- Keep computing provenance and manifest either way: `ValidateSource` (`:634`)
  refuses to build an archive without provenance covering the 13 fields,
  `EvaBundle` carries both as required members, and both are required non-null
  columns on `EvaHandoffRevisions`. Only the zip entry list changes.

**Consequence to accept, not to fix:** changing the JSON bytes changes
`JsonSha256` to `manifest.sha256` to archive SHA to `InputFingerprint`. Existing
`EvaHandoffRevisions` rows stop deduping against a regenerated bundle, so a
regeneration makes Revision 2 rather than replaying Revision 1. Nothing breaks;
replay identity across the change boundary is lost.
