## What

The EVA package becomes the 13-key JSON plus `Images/`, and the JSON is
indented. `manifest.sha256` and `provenance.json` stop being produced at all —
not just omitted from the zip, but removed from the code and the database.

Both paths. There is no longer a per-caller packaging difference.

## Why

**The manifest is not a real requirement.** Operator direction (2026-08-24):
it is an AI invention that entered the governing docs and was never asked for.
Checked, and the claim holds:

- The word "manifest" appears **nowhere** in `reference/` — not in the EVA
  schema, the screenshots, the EVA information notes, or either of the two
  retained JSON examples. That is the whole operator-supplied corpus.
- It entered `docs/frd/frd-07-*` via `2e3db7aa` ("adopt PRD/FRD/ADR taxonomy")
  and `docs/operator-notes.md` via `3f4a35ba` ("release-3 record") — internal
  doc restructuring, not an operator statement.
- The predecessor extractor, whose output EVA actually accepts, emits a bare
  JSON and nothing else.

`provenance.json` goes the same way: operator direction (2026-08-24) is that it
is not needed in the export either, and it has never been an operator concept.

Exporting `ap.QDOS26015` produced a package EVA will not import. Three
independent known-good samples agree with each other and differ from ours:
`reference/eva_information/AX_SP58WVO.json`,
`reference/eva_information/Final Format Example 02.json`, and the operator's
`docs/json-extraction-parity/ap.QDOS26015/old-extraction-working/QDOS_NX14AXY.json`.
All three are 2-space indented and carry no companion files. Ours is minified
and carries two.

The key set and key order are already correct — this ticket does not touch them.

### What is dead, and how it was checked

`ManifestContent` and `ProvenanceContent` are **write-only ballast**: persisted
to `EvaHandoffRevisions` (`EvaHandoffStore.cs:1085-1089`), read straight back
into a reconstructed `EvaBundle` (`:1106-1110`), and then never consumed.
Downloads serve `BundleContent`. Nothing in `src/` reads either — no importer,
no verifier, no UI, no script. Only tests touch them.

Removing them also removes the reason this ticket was going to need a packaging
enum: with no manifest on either path there is only one packaging left, so the
writer gets simpler rather than more configurable.

## Approach

Delete, in `src/Pegasus.Core/Eva/EvaBundleSchema.cs`:

- `WriteManifest` (`:835`), `WriteProvenance` (`:773`), and the
  `ProvenanceFileName` / `ManifestFileName` constants (`:557-558`)
- the two `WriteEntry` calls in `WriteArchive` (`:866-867`)
- `EvaBundle.ProvenanceContent`, `.ProvenanceSha256`, `.ManifestContent` (`:50-52`)

Then `EvaHandoffEntities.cs:16-18`, the `ProvenanceSha256` configuration
(`EvaHandoffModelConfiguration.cs:24`), and a migration dropping the four
`EvaHandoffRevisions` columns.

Flip `WriteOrderedJson` (`:756`) `Indented = false` to `true`. `Utf8JsonWriter`
indents 2 spaces by default, matching all three samples.

Refresh `docs/current-architecture.md:526`, which records the as-built archive
as carrying "provenance and manifest". This ticket changes the as-built shape,
so it owns that line — the normative docs are [[DOCS-013]]'s.

**Keep, deliberately — these are not the invention:**

- `EvaBundle.Sha256` over the whole archive — it is the `InputFingerprint` for
  revision dedupe (`EvaHandoffStore.cs:1081`) and the `Content-Digest` header on
  download (`Download.cshtml.cs:60`).
- the in-memory `EvaFieldProvenance[]` — `ValidateSource` (`:634-664`) uses it to
  check the 13 fields agree with their values. An internal guard, not a shipped
  file. `JsonSha256` likewise stays; it surfaces on revision summaries.

**Consequence to accept, not to fix:** the archive bytes change, so
`InputFingerprint` changes. Existing `EvaHandoffRevisions` rows stop deduping
against a regenerated bundle — a regeneration makes Revision 2 rather than
replaying Revision 1. Nothing breaks; replay identity across the change boundary
is lost.

Blocked by [[DOCS-013]]: FRD-07 currently mandates the manifest, so the doc has
to stop saying so before the code stops doing it.
