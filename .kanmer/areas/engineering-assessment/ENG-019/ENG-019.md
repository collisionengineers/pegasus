## What

Swap the EVA API credentials from the test pair to the live pair.

## Why

[[TICK-077]] delivers the EVA API submission route against the **test**
environment only. EVA uses one base URL for both environments — the environment
*is* the credential pair — so going live is a secret swap and nothing else. No
URL, code or schema change is involved.

## Blocked

**Do not action this ticket without the operator's direct request.** It is
blocked by policy, not by a dependency. The live credentials exist in Infisical
alongside the test pair and must not be used until then.

## Approach

- Confirm the operator's explicit direct request, recorded on this ticket.
- Replace the Key Vault secret values behind `EVA_CLIENT_ID_SECRET_URI` and
  `EVA_CLIENT_SECRET_SECRET_URI` with the live pair, as new secret versions.
- Confirm every `*_SECRET_URI` azd input still names the production vault, and
  that both URIs are versioned.
- Confirm `Eva:RequestFrom` is the contact code issued for the live
  environment — it is credential-scoped and a wrong value returns 400.
- Restart or redeploy Web and Worker so the new secret versions are read.
- Verify with one operator-chosen case, then refresh `docs/operations.md`.

## Verification

- [ ] The operator's direct request is recorded on this ticket.
- [ ] Both secret URIs resolve to live values and are versioned.
- [ ] One real submission reaches the live EVA environment and its returned id
      and File Reference are recorded.
- [ ] `docs/operations.md` reflects the live credential state.
