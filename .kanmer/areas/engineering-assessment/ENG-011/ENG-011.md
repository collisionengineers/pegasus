## Why

One of QDOS26008's photographs shows the odometer and it was not read. Where neither the instruction text nor MOT history yields mileage, the photograph is the only remaining evidence.

## The pattern already exists

The operator asked whether there is a simple AI similar to the VRM reader. There is, and it is this repo's own: ADR-0019 ships an in-process ONNX recognition port — `IVrmRecognitionEngine` (`Pegasus.Core/ImageIntake/VrmRecognition.cs`) backed by `OnnxVrmRecognitionEngine`, `PlateDetector` and `PlateRecognizer` — with a suggestion store, a confidence bar, an abstention taxonomy and staff disposition.

An odometer reader is the same shape: detector crop, then digit recognizer. In-process, no Azure resource, no per-call cost. Azure Document Intelligence is the wrong tool — it reads document layout, not a dashboard.

## Why this is a spike, not a fix

It is a new recognition capability needing its own ADR mirroring ADR-0019 (engine port, model provenance, confidence bar, abstention taxonomy, staff disposition) and a corpus-measured confidence threshold.

It is **not** a prerequisite for correct mileage on QDOS26008 — [[INTK-028]] and [[ENG-010]] are, and both fix real defects. Filed so it stays visible without holding up the regression fixes.
