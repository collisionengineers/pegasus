## What

Ensure an Unidentified item follows the effective destination when a receipt's
manual Case association is reversed or later changed, instead of remaining
permanently resolved to a stale Case.

## Why

Independent review of PR #601 found that the new reconciliation path resolves
an eligible receipt's U-item when `CurrentCaseId` is present, but the supported
`ReverseIntakeLink` path can subsequently clear that association without
reopening or retargeting the terminal Unidentified row. Registration replay
returns the existing resolved row, so the retained material can disappear from
the open queue while having no current destination. This blocks [[INTK-048]]
and relates to [[INTK-029]].

## Approach

- Define the Core-owned synchronization rule for link, unlink, and relink.
- Reuse the existing association and Unidentified mutation owners rather than
  adding a second state derivation.
- Cover link → reconcile → unlink and relink-to-another-Case behavior with Core
  and real-persistence tests.

## Verification

- [ ] Reversing a manually linked receipt does not leave its U-item resolved to
  a Case that is no longer its effective destination.
- [ ] Relinking records the new effective Case without stale target history
  being presented as current state.
- [ ] Canonical Release restore, build, and non-Corpus tests pass.
