## Why

PR #539 reads the Case as `Review` before constructing the package, but `RecordExportAsync` acquires the CaseWorkflow lock without re-reading the locked state. A concurrent Case edit can commit a demotion to `Not ready` between those steps; Export then records and returns a package even though FRD-07 says Export is available only while the Case is in `Review`.

## Required outcome

After acquiring the existing short CaseWorkflow lock, fail closed unless the locked workflow row is still in `Review`. Reuse the existing transaction and state vocabulary; add only the focused concurrency/regression evidence needed. Do not add a new abstraction, compatibility path, or schema.

## Verification

A Case demoted before Export obtains the recording lock does not write `eva_bundle_exported` history or the first-send proxy and does not return a successful bundle.

## Outcome

Resolved in PR #539 at commit cc6b0ee7. Locked-state regression and build pass; not deployed.
