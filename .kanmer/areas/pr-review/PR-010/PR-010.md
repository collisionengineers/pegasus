## What

Harden the TICK-046 exact-message correction boundary so only a defined canonical classification option can reach Core/persistence, and validate `Other` name/reasoning lengths server-side.

## Why

PR #418 currently parses model-bound enum text without `Enum.IsDefined`/canonical-option validation. Values such as `received:999` can throw and `sent:999` can construct an undefined category. Browser `maxlength` is not a server-side boundary, so oversized Other values can reach bounded database columns. This violates MAIL-04's fail-closed invalid-category requirement.

## Verification

- Crafted undefined numeric Received and Sent family values return validation errors and perform no write.
- Oversized Other name/reasoning return validation errors and perform no write.
- The Core operation independently enforces the canonical category shape and bounds rather than trusting Razor controls.
- Focused Core and real page-pipeline tests prove the cases.
