## What
Complete PR #563's Graph webhook validation and executable evidence for malformed, unauthentic, wrongly scoped, lifecycle, batching, and queue-failure paths.

## Why
The implementation tests only the validation handshake and one valid `created` notification. The plan/report claim coverage for invalid input, active tenant/subscription/resource scope, lifecycle notifications, 202-after-send, 5xx-on-send-failure, batch bounds, and secret non-disclosure that is not present. Lifecycle notifications currently bypass resource matching.

## Acceptance
- Every queued notification is authenticated by clientState and validated against the expected tenant, active subscription, and supported resource/scope semantics, including lifecycle events as required by the governing FRD.
- Malformed, unknown, expired, wrong-tenant, wrong-secret, wrong-resource, unsupported-change and over-limit batches enqueue nothing with uniform non-disclosing responses.
- A valid queue-send failure returns a retryable 5xx; successful valid delivery returns 202.
- Tests cover each lifecycle kind and prove the same targeted stable-mailbox wake route.
- The post-implementation report states only evidence actually present.
