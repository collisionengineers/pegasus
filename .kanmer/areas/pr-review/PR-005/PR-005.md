## Why

PR #414 now declares Unicode NFKC normalization as part of the durable RFC Message-ID comparison contract and declares that the original transport value is retained verbatim as evidence. Its regression tests cover ASCII case and surrounding whitespace only, and assert counts rather than the retained raw/canonical values. The highest-risk newly introduced behaviors therefore have no acceptance evidence.

## Required change

Exercise two genuinely Unicode normalization-equivalent RFC identity inputs through the real poll/EF path and prove they produce one receipt/work item/retained row. Assert the retained raw Internet Message-ID remains exactly the first transport value while the separate canonical key is the normalized comparison value. Keep the distinct-canonical-identity control.

Also validate that canonical expansion cannot exceed the configured 500-character database key silently; either bound the canonical output in Core or prove the accepted input domain makes expansion impossible.
