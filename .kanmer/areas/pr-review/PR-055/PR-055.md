## Why

PR #539 checks for an existing `eva_bundle_exported` history row before inserting, but the ActionHistory lookup index is non-unique. Two simultaneous requests using the same operation key can both insert once the first-export proxy already exists, after which `SingleOrDefault` is no longer safe.

## Required outcome

Make exact replay atomic at the database boundary using the repository's existing idempotency convention, and add a concurrent same-key regression test.

## Verification

Two simultaneous identical Export POSTs produce exactly one action-history row and both resolve as the same successful operation; a conflicting reuse is rejected.
