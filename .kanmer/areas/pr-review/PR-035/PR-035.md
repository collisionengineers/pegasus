## What

Keep user-controlled retained search context from causing a classification-correction 500.

## Why

At PR #469 head `7932d683`, `MessageModel.ReloadAsync` passes the GET-bound `search` value into Core without handling validation failures. A POST with invalid classification/correction state plus a whitespace-only or over-200-character `search` query makes the reload throw `ArgumentException` outside the handler catch path. Search context added by MAIL-11 must remain a supported fail-closed request state. This blocks [[TICK-053]].

## Verification

- Exercise authenticated correction POST reload with whitespace-only and overlong search context and prove a supported response rather than 500.
- Reuse the existing normalization/validation convention; add no new validator abstraction.
