## What

Correct the Test UI prototypes whose `default` state omits the current Razor page's defining rendered branch or interaction, and make the catalogue verification evidence match the actual branch.

## Why

[[UIIMP-002]] promises page-specific replicas for every visual route. Several prototypes instead label exceptional or empty branches as `default`: `administration-principal-create--default.html` omits the create-principal form, and `administration-roles--default.html` omits the role-assignment table and form. A route-count pass cannot prove rendered-page fidelity. The current post-implementation claim that `git diff --check` passed is also contradicted by the branch output, which reports trailing blank-line errors across the catalogue.

## Approach

- Compare every visual inventory entry and each named state with its current `.cshtml`, PageModel branches, shared layout, and partials.
- Ensure the `default` prototype includes the route's defining normal interaction; represent exceptional/empty alternatives as separately named states where meaningful.
- Keep static-only behavior and established evidence-safe values; do not add browser-side business policy.
- Remove whitespace errors and strengthen focused review/validation evidence so a route-count success is not presented as page-fidelity proof.
- Update [[UIIMP-002]]'s report and checklist claims to match rerun results.

## Verification

- [ ] Create principal exposes the normal create form in `default`, with the unavailable/no-provider branch separately represented if retained.
- [ ] Staff roles exposes the current role-assignment table/form in `default`, with empty separated if retained.
