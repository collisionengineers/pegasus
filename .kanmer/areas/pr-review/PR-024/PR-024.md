## What

Ensure every retained-mail search result carries an honest visible match location from the same canonical field that admitted the row.

## Why

PR #469 filters retained rows through every `IntakeSearchDocuments.Text` value, including the root message-body projection, but `AddSearchMatchesAsync` labels message-body matches only from `RetainedMailboxMessages.BodyPlainText` and labels projection matches only for attachment rows. The canonical intake-reader body and retained display body are not interchangeable (staff-forward handling is one concrete difference), so a root-projection-only match can admit a row whose `Matches` list is empty. That violates FRD-08's visible match-location contract and blocks [[TICK-053]].

## Verification

- Prove a root search-document term absent from the retained display body cannot return an unlabeled result.
- Preserve retained body, attachment-filename, and attachment-content search before SQL count/paging.
- Reuse the existing retained body and single receipt-owned attachment projection; add no parser, store, or backfill.
