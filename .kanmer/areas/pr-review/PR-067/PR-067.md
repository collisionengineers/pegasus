## What
Correct PR #563's migration so establishing `ApprovedMailbox.Id` does not automatically delete retained mailbox evidence and does not fail when retained messages have restrictive dependants.

## Why
The current migration executes `DELETE FROM RetainedMailboxMessages` during ordinary deployment. ADR-0024 requires any pre-launch reset to be a separately approved exact-target operation and forbids deleting retained business evidence; existing folder-move rows also restrict deletion.

## Acceptance
- Ordinary schema migration preserves retained business evidence or uses an explicitly authorised target-state strategy consistent with ADR-0024.
- The migration succeeds with retained messages, attachments, and restrictive folder-move dependants present.
- Any separately disposable poll/cursor reset is explicit, bounded, and independently approved rather than hidden in deployment.
- Migration and SQL-grant integration tests prove the actual target schema and populated-state path.

## Outcome
Addressed on PR #563 at `fab4b06d`: exact stable-ID mapping preserves retained, attachment, folder-move, poll and poison rows; unmapped identities fail closed; populated migration and grant tests pass.
