## What

`scripts/Test-DocumentationLinks.ps1` excludes the vendored agent-tool skill
trees `.agents`, `.codex`, `.grok` and `.kanmer` from relative-link checking
(`$excluded = '^(node_modules|corpus|artifacts|\.git|\.claude|\.agents|\.codex|\.grok|\.kanmer)/'`)
but not `.opencode`, which the operator commit `c5c7a874` ("chore(kanmer):
add OpenCode skills and localize provider config", already on `origin/dev`)
added as a fifth vendored copy of the same bundled Kanmer skill content. The
bundled `kanmer-setup/SKILL.md` (present byte-for-byte in all four/five
trees) has always linked to a `docs/manual/greenfield.md` that does not exist
in this repository, so only the `.opencode` copy now fails the checker —
purely because the exclusion regex was never extended when that fifth tree
was added.

## Why

Every CI run of the `documentation` lane on `origin/dev` and on every PR
branched from it now fails with:

```
BROKEN .opencode/skills/kanmer-setup/SKILL.md: ../../../../docs/manual/greenfield.md
```

Raised by DOCS-017's PR review (PR #651, 2026-09-03): the finding is real
but out of DOCS-017's scope (`.opencode/**` is not an owned or supporting
path for that ticket, and DOCS-017 does not touch the file — its blob is
identical between `origin/dev` and DOCS-017's head). Left unfixed, this
blocks the required `documentation` check on every EPIC-012 PR, not just
DOCS-017's.

A near-identical regression was fixed once before for `.grok/skills` by
[[PR-065]] (PR #561), but a later Kanmer skill-tree reconciliation
(KANMER-006/KANMER-010, which replace `.agents/skills` and `.grok/skills`
wholesale from the plugin bundle) re-vendored the same unfixed upstream
content, and `.agents/skills/kanmer-setup/SKILL.md` and
`.grok/skills/kanmer-setup/SKILL.md` on current `origin/dev` carry the same
broken link today — they simply don't fail CI because the checker already
excludes those two directories.

## Approach

Add `\.opencode` to the checker's exclusion regex, consistent with the
existing treatment of the other four vendored/tool directories — these are
upstream Kanmer-bundle skill trees, not authored repository documentation,
and this repository does not own their content. Do not edit the vendored
`SKILL.md` files themselves (they are overwritten wholesale by the next
Kanmer setup reconciliation, so a hand fix there would not stick, per the
PR-065 → KANMER-006/010 history above).
