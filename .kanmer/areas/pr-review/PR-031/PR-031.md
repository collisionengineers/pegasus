## What

Map recoverable Azure token-acquisition failures at the Deleted Items external boundary to the existing unavailable state.

## Why

PR #469 maps Graph HTTP and timeout failures, but a managed-identity token acquisition or refresh failure can occur before HTTP and currently escapes as a server error. The workspace must render its honest unavailable state without swallowing caller cancellation. This blocks [[TICK-053]].

## Verification

- Prove an Azure credential/authentication failure returns `DeletedMailSearchState.Unavailable` through the authenticated caller.
- Prove caller cancellation still propagates and no retry framework or new exception taxonomy is introduced.
