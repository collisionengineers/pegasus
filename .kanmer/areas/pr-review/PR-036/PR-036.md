## What

Restrict the Worker grant on `IntakeSearchDocuments` to the operations its implementation actually performs.

## Why

PR #469 claims least-privilege runtime grants, but the Worker receives UPDATE while `EfIntakeReceiptStore` only selects, deletes, and inserts projection rows (`ReplaceSearchDocuments` removes and recreates them with new identities). The extra permission is unsupported by a caller and contradicts the repository's least-privilege evidence. This blocks [[TICK-053]].

## Verification

- Remove Worker UPDATE from the migration and bootstrap permission matrix while retaining SELECT/INSERT/DELETE.
- Run migration-grant/deployment-plan checks and prove the store paths remain green.
