## Why

PR #414 makes mailbox + RFC Internet Message-ID the durable duplicate boundary, but derives the Core intake receipt token from the raw case-sensitive string while the retained-store comparison is `OrdinalIgnoreCase` and SQL Server uniqueness/equality uses the database collation. A case-only or otherwise SQL-equivalent redelivery can therefore create a second intake receipt/business occurrence before retention decides it is the same retained message.

## Required change

Define and reuse one canonical RFC identity representation for the Core receipt token, retained-store lookup/comparison, and persistence uniqueness semantics. Preserve mailbox scope and fail closed on contradictions. Do not weaken distinct RFC message identities.

## Verification

- Add a real poll/EF acceptance test proving equivalent RFC identity representations replay one intake receipt and one retained row.
- Add a test proving genuinely distinct RFC identities remain distinct.
- Confirm the FRD describes the canonical equality rule actually implemented.
