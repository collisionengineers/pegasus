## Why

After a definitive association refusal, the correction attempts `IReleaseCaseEditLease`, catches every recoverable release failure, and then unconditionally clears the only retained lease token. A transient release failure therefore recreates the original five-minute stranded-lease defect with no immediate retry path.

## Required outcome

Keep compensation recoverable when the existing release port cannot confirm success. Preserve the lease token/operation context needed for a bounded retry or otherwise prove immediate editability; do not add a background worker, Mail-specific store, or second lease policy.

## Verification

- [ ] Force a definitive association failure followed by a transient release failure.
- [ ] Prove compensation can be retried and the Case becomes immediately editable once release succeeds.
- [ ] Prove successful release clears protected confirmation state.
- [ ] Preserve same-confirmation retry for uncertain association outcomes.
