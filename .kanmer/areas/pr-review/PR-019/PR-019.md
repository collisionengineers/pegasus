## What

Handle invalid search terms and empty filtered results as explicit search states.

## Why

With an active Inbox search that returns zero rows, the page reports `No mail has been received` rather than `no matches`. A query longer than Core's 200-character limit also reaches the use case without page validation and can become an unhandled server error. Both are user-controlled GET states introduced by PR #469. This blocks [[TICK-053]].

## Verification

- Prove a populated mailbox with no matches names the filter outcome.
- Prove blank/overlong/direct query-string input returns a supported response rather than a 500.
- Preserve current scope and accessible search conventions.
