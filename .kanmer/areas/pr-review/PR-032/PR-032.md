## Why

PR #474 computes a Core unavailable recommendation when `RetainedMailDetail.Classification` is null, but `/Inbox/{id}` renders folder recommendation output only inside the classification-dossier block. A retained message with no dossier therefore exposes no recommendation or unavailable state, contrary to [[TICK-047]]'s ticket body, research, file map, and plan.

## How to verify

- Render an authenticated retained-message detail whose classification dossier is null.
- Assert an accessible `Recommended Outlook folder` unavailable value and reason are visible.
- Preserve the existing classification-evidence rendering for classified and ambiguous outcomes.
- Keep the fix read-only: no persistence, Graph call, operation identity, mutation, or duplicate folder mapping.
