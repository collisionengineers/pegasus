## Why

PR #491 parses and rejects unknown queue keys and Deleted Items plus queue context on GET/reload, but successful exact-message POST handlers execute classification, folder-move, and Case-association work before parsing that context. A forged `queue=needs-sorting` or `folder=deleted&queue=triage` can therefore mutate the exact message and only fail on the redirect.

## Required outcome

Reuse the existing folder/queue parser at the start of every exact-message POST path that carries list context, before acquiring a lease or invoking any mutation. Invalid or Deleted Items plus retained-classification queue context returns not-found with no business call. Do not add a second parser or authorization layer.

## Verification

- [ ] Unknown queue context causes no classification, move, association, or lease call.
- [ ] Deleted Items plus queue context causes no such call.
- [ ] Valid queue context remains preserved through successful and recoverable action paths.
