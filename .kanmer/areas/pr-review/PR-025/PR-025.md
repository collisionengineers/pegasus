## What

Add Web/API caller evidence that authenticated `/Inbox` requests actually traverse the bounded Deleted Items use case and render its approved-mailbox, match, unavailable, truncation, and paging states.

## Why

PR #469 proves the Graph source directly and proves DI composition separately, but `MailWorkspaceWebTests` never executes `/Inbox?folder=deleted_items&search=...`. Its only Deleted Items assertion is the no-search prompt. The ticket plan and repository evidence tiers require the actual route/caller, not registration plus adapter tests, and [[PR-017]] specifically promised Web evidence that an approved mailbox with zero retained rows is selectable. This evidence gap blocks [[TICK-053]].

## Verification

- Exercise the authenticated `/Inbox` route with a controlled Deleted search source and prove a zero-retained-row approved mailbox is selectable.
- Prove matched results and their visible match location plus unavailable/truncated/paged states through rendered HTTP responses.
- Keep the source fake at the external boundary; do not add a second use case, parser, store, or production behavior.
