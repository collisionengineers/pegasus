## Why

The new Mail Case-search result renders only `Review <reference>` inside the focusable link while registration, claimant and stage sit outside it. This conflicts with the design contract that the whole result is keyboard-focusable and all identity text contributes to the accessible name.

## Required outcome

Keep the existing bounded `UploadCaseDecision` suggestions and make each result one clear accessible selection target. Do not add a second result component or client-side search framework.

## Verification

- [ ] Keyboard focus reaches one selection target per result.
- [ ] Its accessible name includes the visible reference, registration, claimant and stage.
- [ ] Existing search, reviewed target summary and return context remain intact.
