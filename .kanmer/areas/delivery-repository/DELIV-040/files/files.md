## Ripple effects

- **Cross-document anchors.** `capabilities.md` links into FRD headings (for example `RPT-02` → `frd-11…#report-draft-entry-point`, `EXT-09` → `frd-06…#professional-engineering-findings-and-correction`, `CASE-18` → `frd-01…#due-work-chasing-and-action-history`), and `open-decisions.md` L11 links eight settled clauses. Editing section *bodies* is safe; renaming a heading is not.
- **`capabilities.md` arithmetic.** The new `ACC-10` row moves four numbers (`Now` 142→143, the two totals 233→234, `0.1.0-alpha.1` 142→143) and the recount date. A row added without them makes the file internally false.
- **Resolved open decisions.** Removing the rate-card row and the mail-freshness section from `open-decisions.md` requires the settled content to exist in its canonical owner first (FRD-11/FRD-06 for D17, FRD-08 for D22) — otherwise the decision is deleted rather than moved.
- **Blocked tickets.** `ENG-031`, `ENG-033`, `INTK-052`, `INTK-054`, `MAIL-030`, `MAIL-031`, `PLAT-059`, `PLAT-062`, `PLAT-064`, `TICK-082` all read these documents as their premise; each leaves Backlog only after this PR merges.
- **ADRs owed elsewhere.** D16's shared Core command with two callers, D17's global versioned rate-card aggregate and D19's normalized curation snapshot are durable technical shapes. This ticket writes only the behaviour; the ADR (next free number after `0037`, which is reserved for OCR) is owed by `ENG-033`/`AUTO-016`, `TICK-082` and `ENG-031` respectively.
- **No code, no tests, no generated artifact.** Nothing under `src/`, `tests/`, `scripts/` or `docs/design/test-ui/` changes, so no snapshot or catalogue regeneration follows.

## Ownership note for the lock

The `governing_docs` file lock — `docs/frd/*.md`, `docs/capabilities.md`, `docs/boundaries.md`,
`docs/open-decisions.md`, `docs/design/README.md` — belongs to **DELIV-040 alone while this ticket
is open**. No other ticket edits any of those paths until this PR merges to `dev`; a ticket that
believes it needs one reports it and waits.

`docs/engineering.md` (tier 10) and `docs/runbook.md` (two release-validation bullets) sit
*outside* that lock but inside this ticket's scope. The implementer touches only the named lines
in those two files, so a concurrent ticket editing an unrelated part of either file is a merge
conflict to resolve, not a lock breach.
