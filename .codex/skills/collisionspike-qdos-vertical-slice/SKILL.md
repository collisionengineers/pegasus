# QDOS vertical slice

Prove one narrow operator path before broadening providers or integrations. Use `$collisionspike-domain`, `$collisionspike-corpus-evaluation`, and `$evidence-led-delivery` together.

## Slice boundary

The minimum slice accepts a genuine local QDOS instruction shape through the same application entry point the Worker will call, derives explicit evidence, creates a reviewable case candidate, allocates the correct QDOS reference atomically when authorized, persists it, and exposes the outcome in the Web inbox or case view.

Do not include valuation, repair estimate, invoice amount, WhatsApp, automated outbound messaging, Maps/Vision, malware scanning, or multi-provider generalization.

## Ordered evidence policy

Define classification and extraction precedence explicitly before writing the classifier. Strong content or document evidence can override weak transport identity such as a staff-forwarded sender. Preserve contradictions for review rather than allowing whichever check runs first to win.

At minimum distinguish:

- QDOS instruction confirmed;
- images-only work identified by registration;
- incomplete or needs sorting;
- unrelated, query, or other;
- unsupported or corrupt input;
- transient technical failure;
- unknown or contradictory evidence.

## Implementation sequence

1. Freeze a redacted, human-reviewed QDOS corpus cohort including staff-forwarded and contradiction examples.
2. Trace and name the production-equivalent caller.
3. Define one input contract and one output decision contract in Core.
4. Extract embedded PDF text locally; detect scanned or insufficient text; keep OCR behind one port.
5. Apply QDOS-specific deterministic parsing in one implementation.
6. Persist idempotently. Allocate `{principal}{YY}{NNN}` with a database-enforced unique constraint and transaction or atomic counter.
7. Render the operator-visible queue or case state and evidence requiring review.
8. Have an independent test agent compare literal rules and frozen expectations.
9. Run holdout inputs and record cohort results, unsupported outcomes, latency, and external-call cost.

## Completion evidence

Completion requires a genuine sample through the actual caller, a stored result, an operator-visible result, correct reference behavior under concurrency, and independent review. Registered handlers, unit tests, or a local parser command alone are insufficient.
