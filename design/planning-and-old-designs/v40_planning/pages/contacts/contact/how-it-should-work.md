# Contact — how it should work

Proposed on 13 October 2026, not yet decided. Each line beginning "Open:" names its lettered item in [v40-notes.md](../../../current/v40-notes.md#6-sign-off-list).

The operator ruled on 13 October 2026 that the type is fixed and shown read-only, with no type grid, and that the page shows only its type's sections. A Principal's panels keep FRD-17's order: Report generation → Report sending → Salvage matrix.

- D1. The contact form has Organisation name; **Type** as a greyed box; and, for a Principal, **Principal code** as a greyed box. Then come Contact person, Phone, Email, Address and Postcode, and for a Principal, Inspection mode and Accepted e-mail identities as greyed boxes. Open: H, I, J, K.
- D2. Sections by type:

  | Type | Sections |
  | --- | --- |
  | Principal | Case guidance |
  | Claim Source | Case guidance, then Linked principals |
  | Repairer, Storage, Third Party Engineer | Linked principals |

  Every type then has Active and **Save contact**. Open: R (Guidance for new Cases).
- D3. Notes on every Case grows to fit its text in the 720px form column. Open: M.
- D4. Linked principals is one list for the contact's type, with no subheading, in three columns. Open: P.
- D5. An active Principal's panels follow, with no Principal settings panel: Report generation (Default fee (£), **Save report settings**), Report sending, Salvage matrix, Default inspection location, Principal API, then **Replace code**. They are stacked, or shown as tabs. Open: K, L.
- D6. A panel's save comes back to that panel with its notice inside it. A refusal shows at the top of that panel and keeps what was typed. **Save contact** returns to the list. Open: N, O.
- D7. Report sending is unchanged: a full edit form, with one spare blank rule row, the five hints and the condition kinds in the live order. Open: S, T (v39 T, U).
- D8. An inactive Principal shows its contact form and "This principal is inactive. Change the settings on its successor.", as today.
- D9. The three defects listed in item Q are fixed. Open: Q.

## Documentation impact when the FRD is written

- FRD-04: one type per contact, fixed at creation; the contact's sections by type; Guidance for new Cases (if R keeps it).
- FRD-17 *Contacts*: the panel list without Principal settings; where a save and a refusal land; tabs, if L chooses them.
