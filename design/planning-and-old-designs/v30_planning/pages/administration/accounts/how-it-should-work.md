# Staff accounts: how it should work

Stage 1 proposals, **not yet decided**. The lettered items are in
[v30-notes.md](../../../current/v30-notes.md#sign-off-list) (items U to Z).

1. The settings dialog head carries the username and the account's state
   chip (Enabled, Disabled, Password change required). The Username/State
   fact grid goes: one fact, one home.
2. On the signed-in Administrator's own account, Role renders as a greyed
   value box, "Administrator", in the same cell a select occupies for any
   other account. No disabled select.
3. Printed name and Qualifications share one two-column row under Role and
   Sign-off Engineer, so the four bounded fields align.
4. The signature is a `settings-line` like the Glass's line: **Signature
   image** · "On file" or "Not on file" · **Replace signature** or **Upload
   signature**, which opens the file picker. The native input is not drawn.
5. One foot. Left: Disable or Enable, Force logout, Reset password, then
   Delete after a gap. Right: Cancel, **Save settings**. On one's own
   account only Cancel and Save settings.
6. The temporary password shows at the top of the list's stack as a
   success notice with the password in mono, not as a panel below the
   table.

Open: U (head chip, fact grid removed), V (Role as a value), W (aligned
fields), X (signature line), Y (one foot), Z (temporary password
placement).
