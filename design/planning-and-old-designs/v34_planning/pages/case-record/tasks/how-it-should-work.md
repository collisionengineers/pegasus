# Tasks: how it should work

Decided with the operator on 6 October 2026. The rules below are what the source now does under those rulings; the round awaits design sign-off.

- **D1.** Tasks is the Case's own section after Notes: a dense table of task, assignee and a state chip (Open, Completed, Cancelled), open tasks first, the same in both views of an Inspection + Audit Case.
- **D2.** In the edit session the head of the section has a **New task** box with **Add task**, and each open task offers **Assign**, **Complete** and **Cancel task**; outside it, and on a Completed, Query, closed or archived Case, the list stands without them.
- **D3.** A task description is required and has no length limit.
- **D4.** Assign chooses from the enabled staff, and Core refuses an account that does not exist or is disabled.
- **D5.** Each action records one fixed reason, so there is no reason box, and the edit session carries on after it.
- **D6.** When Report sent is recorded for a Pegasus report send, each after-send task that send recorded becomes one open, unassigned task in the name of the staff member who sent the report, once only, as system work that keeps any edit session.
- **D7.** A Case with an open task cannot be completed, closed or archived, and the refusal reads "Complete or cancel every open task first."
- **D8.** A task has no due date.
