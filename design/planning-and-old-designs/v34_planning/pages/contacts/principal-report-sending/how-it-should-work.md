# A Principal's Report sending panel: how it should work

Decided with the operator on 6 October 2026. The rules below are what the source now does under those rulings; the round awaits design sign-off.

- **D1.** Every Principal has report sending rules, and a Principal the SOP does not name, or created later, has the default rules: reply to the original sender, keep the instruction's Cc, fee note as a separate PDF, report with vehicle images.
- **D2.** The Report sending panel follows Report generation on an active Principal's Contact page, and the separate Report recipients settings are gone.
- **D3.** Send from is a list of the Approved mailboxes with "Not set"; Send to, Cc, Never cc and Reminders are repeated inputs with an Add button; Send to only, Reply all, Garage figures and the six Attach choices are ticks; Hold and the First send and Re-send names are text.
- **D4.** Rules are repeated rows, each with Match (All or Any condition), at least three condition lines (a kind, then a Contact list, the outcomes, or text), the actions Cc add, Cc remove, Remind, Hold and Stop, and Remove rule, followed by one spare blank row and Add rule.
- **D5.** A blank rule row is ignored, and a condition line with no kind is ignored.
- **D6.** One Save report sending saves the whole panel; a refused save names the field or the rule and the problem and keeps what was typed.
- **D7.** No text in the rules has a length limit.
- **D8.** Only an Administrator may save the rules, and a successor code inherits its predecessor's.
- **D9.** The rules were imported once from the Report Sending SOP v5, with the SOP's TL thresholds and QCL's contract repair line appended to Notes on every Case.
