# Accessibility

## Standard and supported input

Planned V1 supports keyboard and pointer operation, screen readers, 200% zoom,
forced colours, and reduced motion on supported desktop layouts. Mobile staff
UI is not planned.

## Focus, semantics, contrast, content, and errors

Use skip links, landmarks, headings, labelled navigation, semantic
tables/captions/sort state, associated error summaries, visible focus, practical
44px targets, restrained live announcements, and non-colour state cues. Route
hiding never replaces server authorization.

## Verification

The planned procedure is keyboard-only traversal, screen-reader/semantic
inspection, 200% zoom at constrained desktop, forced-colours and reduced-motion
checks, contrast review, and automated accessibility scanning through the real
caller. The current Development proof has no accepted complete accessibility
evidence; onboarding does not claim it.
